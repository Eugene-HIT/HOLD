# MAX30102 胸口模式数据说明

## 1. 文件用途

本目录中的 [max30102_chest_vofa.csv](captures/max30102_chest/20260623_143842/max30102_chest_vofa.csv) 是基于 XIAO ESP32S3 + MAX30102 胸口贴肤场景导出的 PPG 运行时序数据。

这份数据主要用于：

1. 给算法同学交接一份可直接分析的胸口 PPG 时序数据。
2. 同时保留原始 PPG 值、当前固件显示链结果、当前检测链中间量和 beat 触发痕迹。
3. 便于后续对比胸口模式与手指模式在波形形态和触发稳定性上的差异。

## 2. 数据采样口径

### 2.1 采样对象

当前这份数据对应的是 MAX30102 在胸口贴肤模式下的连续采样输出。

建议理解为：

1. `raw_ir` / `raw_red` 是最上游反射值。
2. `avg_ir` / `avg_red` 是当前接触判断窗口上的均值量。
3. `detrended_ir` / `filtered_ir` 是当前固件为了便于观察构造的显示链中间量。
4. `contact_present` / `detector_filtered_ir` / `signal_amplitude` 是当前固件心跳检测链的调试量。
5. `beat_marker` / `bpm` 是当前胸口版固件给出的 beat 事件痕迹和实时心率估计。

### 2.2 采样节拍

当前独立 VOFA 入口按约 10ms 一帧输出，约等于 100Hz 量级的时间分辨率。

因此：

1. CSV 中每一行都是一个时间点的状态快照。
2. 不是“每检测到一次心跳才输出一行”。
3. 整份 CSV 是连续时序，而不是只提取 beat 事件。

### 2.3 时间轴口径

CSV 首列 `device_uptime_ms` 是设备启动后的毫秒计时。

这意味着：

1. 每一行都带有设备本地时间轴。
2. 算法侧可以直接按该列恢复采样时序。
3. 当前没有单独导出的“逐拍事件时间戳表”，但可以结合 `device_uptime_ms` 和 `beat_marker` 反推出当前固件在什么时刻触发过 beat。

## 3. 12 列字段逐列说明

### 1. `device_uptime_ms`

- 含义：设备启动后的毫秒计时。
- 单位：ms。
- 用途：整份 CSV 的时间轴。
- 说明：相邻行通常差约 10ms，但仍会受循环调度和串口输出影响，可能不是绝对等间隔。

### 2. `raw_ir`

- 含义：MAX30102 原始 IR 通道样本值。
- 单位：MAX30102 ADC 原始计数值。
- 用途：胸口 PPG 的主要上游信号之一。

### 3. `raw_red`

- 含义：MAX30102 原始 Red 通道样本值。
- 单位：MAX30102 ADC 原始计数值。
- 用途：作为第二路原始光电反射量保留，用于辅助观察和后续分析。

### 4. `avg_ir`

- 含义：IR 通道在接触存在检测窗口上的均值。
- 单位：MAX30102 ADC 原始计数值。
- 用途：
  1. 观察慢变化趋势。
  2. 判断胸口贴合是否稳定。
  3. 参与当前固件中的接触存在判断。

### 5. `avg_red`

- 含义：Red 通道在接触存在检测窗口上的均值。
- 单位：MAX30102 ADC 原始计数值。
- 用途：保留第二路慢变化参考量；当前胸口版接触判定主要依赖 IR，这一列更多用于分析。

### 6. `detrended_ir`

- 含义：IR 原始样本减去当前显示链直流估计后的去趋势信号。
- 单位：原始计数值差分后的浮点量。
- 用途：去掉慢变直流背景，让胸口交流起伏更容易观察。

### 7. `filtered_ir`

- 含义：对 `detrended_ir` 进一步做轻量平滑后的显示链结果。
- 单位：浮点量。
- 用途：
  1. 便于人工观察胸口主波形。
  2. 压低高频锯齿。
- 说明：这一路是显示链，不完全等同于当前检测链真正使用的内部波形。

### 8. `beat_marker`

- 含义：当前固件检测到 beat 时输出的事件脉冲。
- 单位：事件脉冲显示量。
- 当前取值：`0` 或 `1000`。
- 用途：在时序曲线上明确标出当前固件认定的心跳时刻。
- 说明：
  1. 这列当前是二值事件脉冲，不再跟随 `filtered_ir` 幅值跳变。
  2. `1000` 表示本行对应时刻检测到 beat。
  3. `0` 表示本行不是 beat 触发点。

### 9. `bpm`

- 含义：当前固件根据最近若干次有效 beat 间隔计算出的平均心率。
- 单位：bpm。
- 用途：提供实时节律估计结果。
- 说明：当 beat 检测尚不稳定或有效 beat 数不足时，这一列可能为 `0` 或维持旧值。

### 10. `contact_present`

- 含义：当前固件接触存在判定结果。
- 单位：标志位。
- 当前取值：`0` 或 `1`。
- 用途：判断当前检测链是否认为胸口贴合有效。
- 说明：若这列频繁掉到 `0`，检测链会被重置，beat 识别通常也会不稳定。

### 11. `detector_filtered_ir`

- 含义：当前心跳检测链内部真正使用的滤波后 IR 波形。
- 单位：浮点量。
- 用途：
  1. 观察检测链看到的实际波形。
  2. 判断“肉眼可见波形”和“检测链可用波形”是否一致。
- 说明：这一路比 `filtered_ir` 更接近当前 beat 判定的直接输入。

### 12. `signal_amplitude`

- 含义：当前检测链最近一次候选峰谷对的幅值估计。
- 单位：浮点量。
- 用途：用来和当前 detection profile 中的幅值门限比较。
- 说明：
  1. 这列过小通常说明胸口波形虽然可见，但内部有效峰谷差仍不够。
  2. 这列过大则可能对应体动或明显扰动；当前胸口版已增加超大幅值剔除。

## 4. 当前胸口版固件如何做 beat 检测

当前这份数据对应的 beat 检测链来自 [src/heart_rate_estimator.cpp](src/heart_rate_estimator.cpp)，并在 [src/max30102_xiao_esp32s3_chest_vofa/main.cpp](src/max30102_xiao_esp32s3_chest_vofa/main.cpp) 中启用了胸口专用 profile。

当前胸口版不再使用手指版那种“过零触发”为主的策略，而是：

1. 先做接触存在判断。
2. 对原始 IR 建立直流估计并得到内部 `detector_filtered_ir`。
3. 观察内部滤波信号的斜率翻转：
   - 斜率从负变正时记一个 trough。
   - 斜率从正变负时记一个 peak。
4. 对一组有效 trough -> peak 计算峰谷差 `signal_amplitude`。
5. 使用 trough 和 peak 的时间中点作为当前 beat 的近似时间点。
6. 同时施加三类约束：
   - 幅值不能低于最小门限。
   - 幅值不能高于最大门限；过大时按扰动剔除。
   - 两次 beat 间隔必须落在允许范围内，也就是限制最快更新频率和最慢更新频率。

因此，当前胸口版 beat 判定更适合理解为：

1. 峰谷翻转定位候选
2. 峰谷差做有效性门限
3. 中点插值近似 beat 时间
4. 再叠加节律更新频率限制

## 5. 这份数据里已经包含哪些关键内容

从算法交接角度，这份数据已经包含四类关键内容：

1. 原始信号
   - `raw_ir`
   - `raw_red`

2. 当前显示链中间量
   - `avg_ir`
   - `avg_red`
   - `detrended_ir`
   - `filtered_ir`

3. 当前检测链中间量
   - `contact_present`
   - `detector_filtered_ir`
   - `signal_amplitude`

4. 当前固件 beat 触发痕迹和节律结果
   - `beat_marker`
   - `bpm`

所以如果目的是：

1. 看原始胸口波形。
2. 看当前显示链与检测链的差异。
3. 看当前固件大概在什么位置触发 beat。

这份数据已经够做首轮胸口模式分析。

## 6. 这份数据里目前还没有什么

当前这份 CSV 还没有单独整理好的“逐拍事件表”。

也就是说，目前没有额外单独导出这些字段：

1. `beat_index`
2. `beat_timestamp_ms`
3. `beat_interval_ms`
4. `reject_reason`

因此：

1. 当前可以通过 `beat_marker == 1000` 的行，再结合 `device_uptime_ms`，反推出当前固件在何时触发过 beat。
2. 但它还不是一张专门整理好的“每拍事件列表”。

## 7. 如何看这份数据

### 7.1 如果目的是看胸口贴合质量

优先看：

1. `raw_ir`
2. `avg_ir`
3. `contact_present`

通常：

1. 若 `avg_ir` 平稳且 `contact_present` 长时间保持 `1`，说明当前贴合基本稳定。
2. 若 `contact_present` 频繁掉到 `0`，说明接触或扰动问题仍明显。

### 7.2 如果目的是看胸口交流主波

优先看：

1. `detrended_ir`
2. `filtered_ir`

通常：

1. `detrended_ir` 更接近去直流后的原始交流起伏。
2. `filtered_ir` 更适合人工看胸口主波轮廓和节律。

### 7.3 如果目的是看当前固件为什么识别到或识别不到心跳

优先看：

1. `contact_present`
2. `detector_filtered_ir`
3. `signal_amplitude`
4. `beat_marker`
5. `bpm`

判断方式：

1. 若 `contact_present` 经常为 `0`，优先怀疑接触或扰动。
2. 若 `contact_present` 稳定为 `1`，但 `detector_filtered_ir` 很弱，说明检测链看到的有效交流成分仍偏小。
3. 若 `signal_amplitude` 长期偏小，说明当前峰谷差不够过门限。
4. 若 `signal_amplitude` 偶尔非常大但 `beat_marker` 不触发，通常是被当前扰动上限剔除了。
5. 若 `beat_marker` 周期性出现且 `bpm` 稳定在合理范围，说明当前胸口版检测基本工作正常。

## 8. 已知注意事项

### 8.1 这不是“只保留成功 beat 的事件文件”

这是一份完整运行期时序数据。

因此：

1. 有被当前固件触发为 beat 的时间点。
2. 也有大量普通采样点，并不是每一行都对应一个心跳事件。

### 8.2 `beat_marker` 不是逐拍事件表

这列只是一个事件脉冲列。

它不是：

1. 事件编号
2. 明确整理好的逐拍时间戳表
3. 绝对真值标签

### 8.3 `bpm` 是当前固件估计值，不是医学真值

这一列更适合作为：

1. 当前算法链有没有跑起来的参考
2. 节律是否大致稳定的观测量

不建议直接把它当成最终标注值使用。

### 8.4 若后续要做更严格算法训练，通常还需要补充

1. 更明确的逐拍事件时间戳表
2. 更长时长的稳定胸口数据
3. 不同贴合压力、姿态和轻微体动下的胸口样本
