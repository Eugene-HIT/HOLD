# MAX30102 原始数据读取开发要求

## 头部信息
- 创建者：Eugene
- 创建时间：2026-05-23
- 最后更新时间：2026-05-23
- 文档类型：开发前要求文档
- 所属模块：MAX30102 / PPG 原始数据读取
- 文档用途：指导当前工程完成 XIAO ESP32S3 读取 MAX30102 原始 Red / IR 数据的最小可运行开发任务
- 输入：XIAO ESP32S3 开发板、MAX30102 模块、现有 PlatformIO 根工程、串口监视器、I2C 接线信息
- 输出：可稳定打印 MAX30102 原始 Red / IR 数据的固件、串口验证记录、接线与参数结论

## 1. 文档目的
本文件用于约束当前阶段的 MAX30102 接入开发工作，目标不是直接得到可靠血氧结论，而是先打通“设备识别 -> 初始化 -> FIFO 读取 -> 串口输出原始数据”的最小闭环。

本阶段完成后，应能确认：
- XIAO ESP32S3 与 MAX30102 的 I2C 通路正常
- 设备地址与基本寄存器访问正常
- 能持续读到 Red / IR 原始数据
- 串口日志足以支持下一阶段波形观察和算法验证

## 2. 需求背景
当前项目的上位目标是焦虑检测及引导平复装置，开发指南已明确当前应优先完成“可用、可测、可记录”的 MVP 链路。本任务属于传感器数据通路建设中的第一步，即先验证 PPG 原始数据是否可稳定获得。

根据前期资料整理：
- MAX30102 通过 I2C 通信
- 常见模块地址为 0x57
- FIFO 中的每个 LED 样本为 3 字节，实际有效位为 18 位
- 在 Red + IR 模式下，每组样本应包含 Red 与 IR 两路原始值
- 当前阶段应优先验证原始数据和波形可读性，不将血氧绝对值作为本阶段目标

## 3. 本阶段目标定义
本阶段必须完成以下目标：

1. 硬件连线确认
- 明确 MAX30102 与 XIAO ESP32S3 的供电、GND、SDA、SCL 接线
- 首轮仅要求接通 VIN、GND、SDA、SCL
- INT 引脚暂不作为必需依赖

2. I2C 识别确认
- 上电后可扫描到 MAX30102 设备
- 设备地址确认并写入串口日志

3. 传感器初始化
- 配置为可输出 Red + IR 原始数据的模式
- 明确样本率、LED 电流、脉宽、ADC 量程等本阶段采用的初始参数

4. 原始数据读取
- 周期性从 FIFO 读取 Red / IR 数据
- 将读取结果以可观察格式输出到串口
- 能在手指接触与离开时观察到明显变化

5. 最小验证闭环
- 串口监视器中可持续看到时间序列数据
- 数据不应长期全零、全满或明显卡死
- 至少完成一次“未接触”和“一根手指稳定接触”对比验证

## 4. 范围说明

### 4.1 本阶段包含
- MAX30102 基础接线与上电验证
- I2C 地址识别
- 基础寄存器初始化或基于可靠库的初始化
- FIFO 原始 Red / IR 数据读取
- 串口日志输出
- 最小可复现测试步骤记录

### 4.2 本阶段不包含
- 心率算法准确率优化
- 血氧计算与医学级标定
- 多部位测量方案比较
- 运动伪影补偿
- BLE 上传、云端存储或 UI 展示

## 5. 输入与输出

### 5.1 输入
- 开发板：XIAO ESP32S3
- 传感器：MAX30102 模块
- 开发环境：PlatformIO 根工程
- 通信方式：I2C
- 串口速率：115200
- 测试对象：裸模块静态接触测试

### 5.2 输出
- 一份可编译、可烧录的 MAX30102 原始数据测试固件
- 串口中连续输出的 Red / IR 原始数据
- 接线记录与引脚定义结论
- 一份最小验证说明，能够指导重复测试

## 6. 约束条件
- 必须先完成原始数据读取，再进入心率或血氧推导
- 不允许为了“先跑起来”而直接输出 BPM / SpO2 伪结果替代原始数据验证
- 不允许在未确认 I2C 通路前直接把问题归因于算法
- 本阶段优先使用稳定、可解释的配置，不追求复杂优化
- 串口输出必须保留足够上下文，至少包含时间戳或采样序号、Red 值、IR 值
- 代码改动应尽量局限在当前根工程内，保持可回退和可复现

## 7. 依赖项
- 当前工作区已有可正常编译烧录的 XIAO ESP32S3 PlatformIO 根工程
- 当前工作区已有基础串口输出能力
- MAX30102 模块供电与电平必须与 XIAO ESP32S3 兼容
- 需要一份可靠的 MAX30102 初始化依据：官方资料、成熟开源库或已验证寄存器配置说明

## 8. 接线要求
建议先采用以下接线作为首轮验证方案：

- 3V3 -> MAX30102 VIN
- GND -> MAX30102 GND
- XIAO SDA -> MAX30102 SDA
- XIAO SCL -> MAX30102 SCL

说明：
- 若当前工程尚未固定 I2C 引脚，应先以 XIAO ESP32S3 当前 Arduino/板卡默认 Wire 引脚为准，再在代码或文档中明确最终使用脚位
- INT 可后续接入，本阶段不是必须项
- 若模块板载上拉、电源或丝印与常见版本不同，应以实物为准补充修订

## 9. 模块划分

### 9.1 设备发现模块
- 负责 I2C 总线初始化
- 负责扫描并确认 0x57 设备是否存在
- 在串口打印识别结果

### 9.2 传感器初始化模块
- 负责复位与基本寄存器配置
- 设置为 Red + IR 测量模式
- 固定一组初始参数，供本阶段验证使用

### 9.3 数据读取模块
- 负责从 FIFO 中读取 Red / IR 原始值
- 对 18 位有效数据做正确拼接与掩码处理
- 输出统一格式的数据结构或日志行

### 9.4 日志与验证模块
- 负责串口打印启动信息、设备识别信息、实时数据和异常信息
- 必要时打印“未检测到设备”“FIFO 无新数据”等诊断信息

## 10. 推荐开发流程

1. 确认接线
- 先只接最小四线：VIN、GND、SDA、SCL

2. 跑 I2C 扫描
- 确认是否能扫描到 0x57
- 若扫不到，优先排查供电、接线、引脚映射和模块损坏

3. 接入 MAX30102 初始化
- 先使用最少且可解释的配置项
- 明确输出当前使用的关键参数

4. 实现 FIFO 读取
- 先低频打印原始 Red / IR 数据
- 保证日志可读，不要一次输出过多无结构内容

5. 做静态接触测试
- 先观察无接触时数据状态
- 再用一根手指稳定覆盖传感头，观察 Red / IR 变化趋势

6. 记录验证结果
- 记录是否识别到设备
- 记录是否持续输出数据
- 记录手指接触后数据是否明显变化

## 11. 推荐初始验证策略
- 第一轮只验证“能读到值”与“接触时有变化”
- 读数刷新频率以串口可读为准，宁可慢一点，也不要先追求高频
- 若读数波动大，优先先做稳定接触和遮光，而不是立刻改算法
- 首轮建议使用指腹测试，不以颈后、耳后等复杂位点作为主验证位置

## 12. 验收标准
满足以下条件，才算本阶段完成：

1. 固件可在当前根工程成功编译和烧录
2. 串口启动信息中能明确显示 MAX30102 是否被识别
3. 能连续输出 Red / IR 原始数据
4. 手指接触前后数据存在可观察差异
5. 已记录本阶段采用的接线、地址、初始化参数和验证结论

## 13. 风险与待确认事项

### 13.1 风险
- 不同 MAX30102 模块的电源与上拉设计可能不同，实物兼容性需确认
- 若 I2C 引脚选错，容易误判为模块异常
- 贴合压力、环境光和手指摆动会明显影响原始数据稳定性
- 若直接使用第三方库，需确认该库是否兼容 MAX30102 而不是只兼容其他 MAX3010x 型号

### 13.2 待确认事项
- 当前实际使用的 XIAO ESP32S3 I2C 引脚最终定义
- 当前 MAX30102 模块的丝印引脚含义是否与常见版本一致
- 本阶段是采用寄存器直接配置，还是先使用成熟库快速打通链路
