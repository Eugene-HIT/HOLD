# ICS43434 原始数据读取开发要求

## 头部信息
- 创建者：Eugene
- 创建时间：2026-05-24
- 最后更新时间：2026-05-25
- 文档类型：开发前要求文档
- 所属模块：ICS43434 / I2S 数字麦克风原始数据读取
- 文档用途：指导当前工程完成 XIAO ESP32S3 读取 ICS43434 原始音频样本，并以与当前板载灯和心率状态行一致的节拍完成最小可观测验证
- 输入：XIAO ESP32S3 开发板、ICS43434 麦克风模块、现有 PlatformIO 根工程、串口监视器、I2S 接线信息
- 输出：可稳定读取 ICS43434 样本的固件、串口观测结果、接线与参数结论

## 1. 文档目的
本文件用于约束当前阶段的 ICS43434 接入开发工作。本阶段目标不是做录音、降噪、关键词识别或情绪识别，而是先打通“模块接线 -> I2S 初始化 -> 连续读样本 -> 串口看到数据变化”的最小闭环。

本阶段完成后，应能确认：
- XIAO ESP32S3 与 ICS43434 的供电和 I2S 接线正确
- I2S 接收链路已正常工作
- 能稳定获取连续音频样本
- 串口输出足以判断麦克风是否正在读到有效数据

## 2. 需求背景
当前项目的上位目标是焦虑检测及引导平复装置，开发指南已明确当前应优先完成“可用、可测、可记录”的 MVP 链路。麦克风模块在当前阶段的职责不是提供最终算法结论，而是先确认声音输入通路是否可用，为后续声音特征提取、事件检测或多传感器联合分析提供基础。

根据当前已确认资料：
- ICS43434 是数字 MEMS 麦克风，输出为 I2S 音频数据，不是模拟电压
- 模块通常至少需要 3V3、GND、BCLK、WS 或 LRCL、DOUT 这些连接
- SEL 引脚用于选择 Left 或 Right 声道，单麦克风最小验证时只需固定到一个声道
- 该模块适合先做“窗口统计量串口输出”，而不是直接把每个采样点全部刷到串口
- 当前工程现有节拍中，板载用户灯每 250ms 翻转一次，心率状态每 500ms 输出一行，因此麦克风状态输出应优先对齐到 500ms 节拍，内部批处理建议对齐到 10ms 主循环轮询节拍

## 3. 本阶段目标定义
本阶段必须完成以下目标：

1. 硬件连线确认
- 明确 ICS43434 与 XIAO ESP32S3 的 3V3、GND、BCLK、WS、DOUT 接线
- 明确 SEL 引脚固定方式
- 不依赖额外放大、存储或无线链路

2. I2S 输入初始化
- 在当前根工程中完成 I2S 接收配置
- 明确本阶段采用的采样率、位宽、声道配置和 DMA 基本参数
- 明确麦克风内部样本批处理节拍与串口状态输出节拍

3. 原始样本读取
- 周期性从 I2S 读取一批音频样本
- 能区分“读取成功”“无样本”“初始化失败”这些最小状态

4. 串口最小观测输出
- 串口只输出是否读到数据及少量统计结果
- 输出必须便于肉眼判断环境安静、敲击、说话等变化
- 串口状态行默认按 500ms 一次输出，与当前心率状态行节拍一致
- 不要求复杂格式，不要求做音频播放或保存

5. 最小验证闭环
- 在安静环境下可看到稳定非固定值输出
- 对麦克风轻敲、近距离说话或吹气时，串口统计值应明显变化
- 若模块断开或配置错误，串口应能输出明确失败状态

## 4. 范围说明

### 4.1 本阶段包含
- ICS43434 最小接线与供电验证
- I2S 接口初始化
- 连续音频样本读取
- 串口输出最小观测信息
- 最小可复现测试步骤记录

### 4.2 本阶段不包含

- 声纹识别、关键词识别、情绪分类
- 麦克风阵列、多通道同步
- 与 MAX30102 的联合算法处理

## 5. 输入与输出

### 5.1 输入
- 开发板：XIAO ESP32S3
- 传感器：ICS43434 I2S 数字麦克风模块
- 开发环境：PlatformIO 根工程
- 通信方式：I2S
- 串口速率：115200
- 测试对象：安静环境、手敲模块、近距离说话

### 5.2 输出
- 一份可编译、可烧录的 ICS43434 最小读取测试固件
- 串口中按约 500ms 周期输出的读取状态和简要统计值
- 接线记录与引脚定义结论
- 一份最小验证说明，能够指导重复测试

## 6. 约束条件
- 必须先完成“可读到样本”的验证，再考虑任何音频算法
- 不允许为了图快而改成模拟麦克风读取方案，必须按 ICS43434 的 I2S 数字链路实现
- 不允许把“串口持续有打印”误当成“已经读到有效样本”，必须输出与样本内容相关的统计值
- 不允许首轮就全量打印原始 PCM 流，这会降低串口可读性并干扰判断
- 本阶段只需要最小状态提示，不增加与当前目标无关的复杂提示文案
- 麦克风模块的内部批处理节拍建议与当前主循环传感器轮询一致，优先按 10ms 收一批样本再更新统计状态
- 麦克风模块的串口状态输出默认按 500ms 一行，与当前心率状态日志和板载灯完整明灭周期保持一致
- 代码改动应尽量局限在当前根工程内，保持可回退和可复现

## 7. 依赖项
- 当前工作区已有可正常编译烧录的 XIAO ESP32S3 PlatformIO 根工程
- 当前工作区已有基础串口输出能力
- XIAO ESP32S3 所用 Arduino / ESP32 框架需支持 I2S 输入
- 需要一份可靠的 ICS43434 接线与工作方式依据

## 8. 接线要求
建议先采用以下接线作为首轮验证方案：

- 3V3 -> ICS43434 3V / VIN
- GND -> ICS43434 GND
- D8 / GPIO7 -> ICS43434 BCLK
- D9 / GPIO8 -> ICS43434 WS / LRCL
- D10 / GPIO9 -> ICS43434 DOUT / SD
- GND -> ICS43434 SEL

说明：
- 以上为本阶段建议初始映射，若实物焊接或后续测试更适合其他 GPIO，可调整，但必须在代码和总结文档中写明最终使用脚位
- SEL 固定到 GND 时，默认按单麦克风的一个固定声道读取；若后续发现声道不匹配，可切换到 3V3 后复测
- ICS43434 为数字麦克风，不接 ADC 引脚，不走 analogRead 路线
- 模块应使用 3.3V 供电，不按 5V 逻辑接法处理

建议在接线和实物核对时按下表确认丝印对应关系：

| 麦克风模块常见丝印 | 本文含义 | 建议连接到 XIAO ESP32S3 |
| --- | --- | --- |
| 3V / VIN / VDD | 3.3V 供电输入 | 3V3 |
| GND | 地 | GND |
| SCK / BCLK / CLK | I2S 位时钟 | D8 / GPIO7 |
| WS / LRCL / LRC | I2S 字选择时钟 | D9 / GPIO8 |
| SD / DOUT / DATA | I2S 串行数据输出 | D10 / GPIO9 |
| SEL / L-R / LR | 声道选择 | 首轮先接 GND |

补充说明：
- 若实物只有 `L/R` 没有 `SEL`，按声道选择引脚理解即可，首轮同样先接 GND
- 若模块同时给出 `L` 和 `R` 说明而没有明确高低电平表述，应以实物资料为准，并在总结文档中记录最终验证结果
- 若首轮接 GND 后样本明显异常或近似静默，再尝试改接 3V3 做一次对照验证

## 9. 模块划分

### 9.1 I2S 配置模块
- 负责设置 BCLK、WS、DOUT 引脚
- 负责配置采样率、位宽、声道和 DMA 缓冲
- 负责输出初始化成功或失败日志

### 9.2 数据读取模块
- 负责周期性读取一批样本
- 负责统计本批样本的最小值、最大值、均值绝对值或峰峰值等简要指标
- 负责区分读取成功与失败
- 内部读取与统计状态更新优先按约 10ms 节拍执行，便于和当前主循环节拍统一

### 9.3 串口观测模块
- 负责按固定频率输出简洁状态行
- 输出内容应以“是否读到样本”和“样本变化是否明显”为核心
- 默认按 500ms 输出一行，与当前心率状态输出节拍保持一致
- 避免堆叠无关提示语

## 10. 推荐开发流程

1. 确认接线
- 先只接 3V3、GND、BCLK、WS、DOUT、SEL 六线

2. 完成 I2S 初始化
- 先固定单声道读取
- 先采用保守、稳定的采样参数，例如 16000Hz 或同量级配置
- 同时固定内部批处理节拍，优先按约 10ms 聚合一次新样本

3. 实现批量读样本
- 一次读取固定数量样本
- 先验证连续读取是否成功，再决定统计方式
- 统计状态优先在每次 10ms 批处理后更新一次

4. 增加串口统计输出
- 默认每 500ms 输出一行状态
- 推荐输出字段：状态、样本数、最小值、最大值、峰峰值、平均绝对值
- 该节拍应与当前心率状态日志一致，便于后续多模块串口联调

5. 做安静与扰动对比测试
- 安静放置时观察统计值是否稳定但非恒定
- 轻敲、说话、吹气时观察统计值是否明显变大或波动增强

6. 记录验证结果
- 记录接线方案
- 记录采样参数
- 记录在安静和扰动条件下的串口现象

## 11. 推荐初始验证策略
- 第一轮只验证“能读到变化中的样本”
- 串口不直接打印整段 PCM，而是打印 500ms 观测窗口的统计结果
- 若一直读到全零或固定值，优先排查声道选择、引脚映射、I2S 配置和供电
- 若有明显变化但数值偏大或偏小，本阶段只记录现象，不在今晚扩展到音频标定
- 若模块已能稳定出样本，但串口节拍与现有心率状态行不一致，优先先把打印周期收敛到 500ms，再继续比较多模块表现

## 12. 验收标准
满足以下条件，才算本阶段完成：

1. 固件可在当前根工程成功编译和烧录
2. 串口启动信息中能明确显示 I2S 初始化是否成功
3. 能按约 500ms 周期输出样本读取状态和统计值
4. 安静环境与近距离扰动之间存在可观察差异
5. 已记录本阶段采用的接线、引脚、采样参数和验证结论

## 13. 风险与待确认事项

### 13.1 风险
- 若将 ICS43434 误按模拟麦克风接法处理，会导致路线完全错误
- 若 BCLK、WS、DOUT 任一映射错误，通常表现为读不到有效样本或数据异常固定
- 若 SEL 固定声道与软件读取配置不匹配，可能出现数据异常弱或无效
- 若串口输出频率过高，会掩盖有效结论并影响观察
- 若麦克风状态节拍和现有 LED / 心率状态节拍差异过大，会增加后续多模块联调时的判读成本

### 13.2 待确认事项
- 当前实物模块丝印中 3V、WS、SCK、SD、L/R、SEL 的最终命名与接线对应关系
- 当前工程是采用 Arduino-ESP32 I2S 新接口还是兼容旧接口实现
- 首轮最终固定的采样率和读取批大小

本阶段完成后，下一步应按以下顺序推进：
