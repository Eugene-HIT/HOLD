# 完整版融合固件开发规划

## 头部信息
- 创建时间：2026-06-15
- 最后更新时间：2026-06-15
- 文档类型：开发前要求文档 / 集成规划文档
- 所属模块：主线集成固件 / 多传感器融合 / 呼吸引导反馈
- 文档用途：在当前已完成的独立实验基础上，规划“完整版融合固件”的状态机、模块边界、输入输出、触发逻辑与阶段实施顺序
- 输入：现有 MAX30102、MPU6050、AD8232、压力传感器、DRV2605L/LRA 独立实验入口；当前主线代码；用户提出的完整使用流程
- 输出：一份可直接指导下一阶段主线集成开发的结构化规划文档

## 1. 文档目的
本文件用于把当前已经验证过的独立功能，收敛为一个“可长期演进的完整版融合固件”开发规划。

本阶段目标不是一次性把所有功能堆进一个入口，而是先明确：
- 哪些能力已经可复用
- 哪些判断逻辑可以先用简单阈值法落地
- 哪些状态必须拆成独立子流程
- 主线入口和实验入口如何共存

本文件默认遵循以下原则：
- 主线集成代码应成为新的 MVP 主入口
- 已有独立实验入口继续保留，不删除、不注释封存
- 第一版融合逻辑优先保证闭环可运行，再逐步细化算法
- 不允许把尚未验证的复杂 HRV / 焦虑判定模型写成既定事实

2. IMU 呼吸链路

- 已实现“上电引导式个体化校准 + 个人参数运行”

3. 压力输入链路

4. ECG 链路

- 但本次用户给出的完整版主流程，当前主触发逻辑优先围绕胸口 PPG + IMU，不强制把 AD8232 纳入首版融合闭环

5. 震动反馈链路
- 已存在 DRV2605L + LRA 独立深呼吸震动实验入口
- 已验证 RTP 模式的呼吸节律包络输出

## 3. 本次确认的产品级主流程
基于本次用户输入，当前计划的主线产品流程应收敛为以下逻辑：

### 3.1 默认佩戴启动流程
设备正常佩戴后，上电先进入一次 IMU 呼吸姿势校准流程。

校准阶段目标：
- 完成胸口 IMU 当前佩戴姿势下的个人化呼吸基线学习
- 学习正常呼吸、深呼吸、叹气等特征参数
- 锁定当前主要呼吸敏感轴

说明：
- 该流程已在 [src/mpu6050_xiao_esp32s3_respiration/main.cpp](src/mpu6050_xiao_esp32s3_respiration/main.cpp) 中有独立实验实现
- 第一版完整版固件默认仍采用“每次上电重新校准”，暂不要求持久化写入 Flash

### 3.2 正常佩戴实时检测流程
校准完成后，默认进入“胸口佩戴实时监测”状态。

实时并行运行模块：
- IMU 呼吸检测
- 胸口位点 PPG 检测

其中：
- IMU 负责呼吸节律主检测和运动门控
- 胸口 PPG 在贴身有效时，负责心率与后续 HRV 趋势分析

### 3.3 胸口外侧佩戴分支
若设备佩戴在衣服外侧：
- 胸口 PPG 默认失效
- 本阶段不额外做复杂失效检测或纠错处理
- 系统仍继续基于 IMU 实施呼吸监测与呼吸急促触发逻辑

说明：
- 这意味着首版主状态机不强制依赖 PPG 可用性
- 胸口 PPG 只在内侧贴肤时参与心率和 HRV 相关判断

### 3.4 呼吸异常触发分支
若 IMU 检测到呼吸过于频繁：
- 使用可配置阈值判断“呼吸急促”
- 触发主动呼吸引导功能
- 引导方式采用现有 DRV2605L + LRA 震动反馈方案

第一版建议：
- 呼吸阈值先做成显式可配置参数
- 可先使用“连续 N 个有效呼吸周期均超过阈值”再触发
- 不建议仅用单个瞬时周期直接触发

### 3.5 内侧佩戴 PPG 分支
若设备佩戴在内侧，胸口 PPG 可用时：
- 实时检测心跳
- 进一步做简单 HRV / 节律异常趋势判断

第一版判断目标：
- 静止条件下心率明显升高
- 或 HRV 明显不规律 / 异常

达到阈值后：
- 同样触发震动反馈引导呼吸

说明：
- 本阶段仅允许做“工程级简单判断”
- 不允许在首版中把该判断包装成心理或医学诊断结论

### 3.6 主动按压触发的指部 PPG 测量流程
按压压力传感器后：
- 触发主动检测模式
- 震动一下作为开始提示
- 进入“一分钟指部 PPG 检测流程”
- 完成后分析并输出报告结果

当前理解的流程语义：
- 日常佩戴主线是胸口 IMU + 胸口 PPG
- 用户主动按压时，切换到“手指接触式高质量 PPG 测量”子流程
- 该子流程更适合输出一个短时结果报告，而不是只做后台趋势

## 4. 推荐主状态机结构

### 4.1 顶层状态
建议第一版完整固件按以下顶层状态组织：

1. `BOOT`
- 上电、串口、配置、模块初始化

2. `CALIBRATION_IMU`
- 运行 IMU 个体化呼吸校准流程

3. `MONITOR_PASSIVE`
- 被动持续监测
- 并行运行胸口 IMU 与胸口 PPG

4. `GUIDED_BREATHING`
- 进入主动震动呼吸引导状态

5. `ACTIVE_FINGER_PPG`
- 用户按压触发的一分钟指部 PPG 主动检测状态

6. `REPORT_OUTPUT`
- 输出主动测量结果或阶段性总结结果

### 4.2 状态迁移建议

`BOOT -> CALIBRATION_IMU`
- 初始化通过后默认进入

`CALIBRATION_IMU -> MONITOR_PASSIVE`
- IMU 校准完成后进入

`MONITOR_PASSIVE -> GUIDED_BREATHING`
- IMU 呼吸频率异常触发
- 或内侧胸口 PPG 的静止高心率 / 简单 HRV 异常触发

`GUIDED_BREATHING -> MONITOR_PASSIVE`
- 一次固定时长呼吸引导完成后返回

`MONITOR_PASSIVE -> ACTIVE_FINGER_PPG`
- 压感按压触发

`ACTIVE_FINGER_PPG -> REPORT_OUTPUT`
- 一分钟主动指部 PPG 测量完成后进入

`REPORT_OUTPUT -> MONITOR_PASSIVE`
- 报告输出结束后返回被动监测

## 5. 各模块在完整版中的角色定义

### 5.1 IMU 模块
角色定位：
- 主呼吸检测通道
- 佩戴姿势个体化校准通道
- 运动门控通道

第一版要求：
- 直接复用当前 IMU 呼吸实验中的校准与运行主骨架
- 对外暴露统一结果结构，例如：
  - `breath_rate_bpm`
  - `breath_interval_s`
  - `motion_level`
  - `signal_quality`
  - `calibration_ready`

### 5.2 胸口 PPG 模块
角色定位：
- 内侧贴肤时的实时心率和节律辅助通道
- 为后续简单 HRV 判断提供原始 beat-to-beat 基础

当前边界：
- 现有 [src/max30102_xiao_esp32s3_vofa/main.cpp](src/max30102_xiao_esp32s3_vofa/main.cpp) 主要用于手指与胸前位点对比展示
- 它还不是“胸口最终产品算法”
- 因此完整版固件中，胸口 PPG 需要新增“胸口运行参数组”，不能直接照搬手指式判断逻辑

### 5.3 压感模块
角色定位：
- 用户主动触发输入
- 不承担复杂情绪判定

第一版要求：
- 明确按压触发阈值
- 增加去抖和长按/短按判断
- 只保留一个明确动作：进入主动指部 PPG 测量流程

### 5.4 震动反馈模块
角色定位：
- 呼吸引导输出主通道
- 主动指部 PPG 测量启动提示通道

第一版要求：
- 复用现有 LRA RTP 呼吸包络方案
- 新增一个简短“单次确认震动”用于主动测量开始提示

### 5.5 指部 PPG 主动检测子流程
角色定位：
- 用户主动发起的一分钟高质量短时检测
- 输出一个较高置信的阶段报告

第一版建议输出项：
- 测量是否完成
- 指部接触质量是否基本合格
- 平均心率
- 最小/最大心率
- 简化 HRV 指标，例如 RMSSD 或平均 R-R 波动量
- 简单结论文案，例如：
  - 节律较稳定
  - 节律波动偏大
  - 数据质量不足

## 6. 第一版判断逻辑建议

### 6.1 呼吸急促判断
第一版不建议做复杂模型，先做规则法：

- 前提：`motion_level` 为 still 或 light
- 条件：最近若干个有效呼吸周期对应 `breath_rate_bpm` 连续高于阈值
- 阈值：先做成可配置，例如 `kRapidBreathThresholdBpm`
- 防误触：要求连续满足一段时间或连续满足若干次事件

### 6.2 静止高心率判断
建议第一版规则：

- 前提：IMU 判断静止或轻微运动
- 条件：胸口 PPG 有效
- 心率在一段持续时间内明显高于个人静止阈值或经验阈值

第一版可选两条路径：

1. 先用固定阈值
- 例如静止心率持续高于某阈值 N 秒

2. 再升级到个人基线偏移
- 例如高于近期静止均值一定幅度

### 6.3 简化 HRV 异常判断
当前建议只做工程级简单判断，不做复杂频域解释：

- 先基于 beat-to-beat 间隔计算短窗离散程度
- 可先用：
  - R-R 间期标准差
  - RMSSD
  - 连续异常间隔比例

第一版目标：
- 只判断“较稳定 / 波动偏大 / 数据不足”
- 不输出医学术语化结论

## 7. 指部 PPG 主动检测流程建议

### 7.1 启动条件
- 用户按压压力传感器
- 压感超过触发阈值并通过去抖确认

### 7.2 子流程
1. 输出一次短震动提示
2. 提示开始指部 PPG 测量
3. 进入固定 60 秒采样窗口
4. 在窗口内做接触质量与数据质量判断
5. 计算基础指标
6. 输出简短报告

### 7.3 第一版报告建议
建议报告只做开发者和 MVP 可读版本，例如：

- `session_duration_s`
- `signal_quality`
- `finger_present_ratio`
- `avg_bpm`
- `min_bpm`
- `max_bpm`
- `rr_variability_level`
- `summary_text`

## 8. 实现分阶段建议

### 阶段 1：建立融合主入口骨架
目标：
- 新建完整版主入口 env
- 只完成状态机空骨架与模块初始化顺序
- 保留现有实验 env 不动

### 阶段 2：接入 IMU 校准 + 运行主链
目标：
- 先把 IMU 呼吸链完整接入主入口
- `BOOT -> CALIBRATION_IMU -> MONITOR_PASSIVE` 跑通

### 阶段 3：接入震动引导闭环
目标：
- 呼吸急促时触发 `GUIDED_BREATHING`
- 跑通“检测 -> 震动引导 -> 返回监测”最小闭环

### 阶段 4：接入胸口 PPG 被动分支
目标：
- 加入胸口 PPG 实时心率输入
- 先只做心率可用性和静止高心率判断

### 阶段 5：接入主动指部 PPG 子流程
目标：
- 压感触发
- 60 秒主动测量
- 输出最小报告

### 阶段 6：补充简化 HRV 判断
目标：
- 在指部 PPG 或胸口 PPG 中引入短窗简单 HRV 指标
- 将其纳入触发条件或报告内容

## 9. 当前最关键的待确认事项

### 9.1 已确认：胸口 PPG 与指部 PPG 共用同一 MAX30102 实体
当前已确认：
- 使用同一颗 MAX30102
- 在不同使用状态下切换“胸口被动监测”和“指部主动检测”两套参数与流程

工程含义：
- 首版完整固件不需要引入第二颗 PPG 模块
- 代码层必须显式区分 `chest_ppg_profile` 与 `finger_ppg_profile`
- 状态机切换到 `ACTIVE_FINGER_PPG` 时，应暂停胸口被动 PPG 判断并切换参数组

### 9.2 已确认：指部主动检测的交互形态
当前已确认：
- 用户直接把手指紧贴在反射式 PPG 模块表面进行主动检测
- 当前版本默认用户已经贴住，不额外引入复杂接触引导
- 压感与主动检测的联动细化后续再考虑

工程含义：
- 第一版主动检测流程可默认“进入状态后立即开始质量观察与计时”
- 当前不强制等待复杂的多阶段接触确认界面
- 但仍建议内部保留最小信号质量判断，避免完全无效数据也照常出报告

### 9.3 胸口 PPG 的“失效不处理”边界
目前理解为：
- 衣服外侧佩戴时，胸口 PPG 无效属于正常情况
- 主系统不额外提示错误，只继续依赖 IMU 跑呼吸监测

需要确认是否要补最小状态标记：
- 例如仅内部标记 `ppg_quality=invalid`
- 不对用户做复杂提示

### 9.4 胸口 PPG 触发判断是否需要“静止前提”硬门控
当前建议是需要。

原因：
- 否则胸口 PPG 在运动或体位变化时，误触发高心率和 HRV 异常的概率会明显上升

### 9.5 已确认：第一版完整版暂不纳入 AD8232
当前已确认：
- 第一版融合固件不把 AD8232 并入主闭环
- AD8232 保留为后续高可信节律参考或独立验证链

工程含义：
- 首版主线可以收敛为 IMU + MAX30102 + 压感 + DRV2605L/LRA
- 当前不必处理 ECG 电极贴附、导联脱落和额外 ADC 实时路径
- 状态机、任务调度和功耗结构都可明显简化

## 10. 当前补充建议

1. 完整版主线第一版应先围绕“IMU + 胸口 PPG + 震动引导 + 指部 PPG 主动检测”建立统一状态机，但实现阶段仍建议先跑通 IMU + 震动引导闭环，再逐步并入胸口 PPG 和指部 PPG。

2. 胸口 PPG 与指部 PPG 建议在代码层明确区分成两套参数组：
- `chest_ppg_profile`
- `finger_ppg_profile`

3. 胸口 PPG 的第一版目标应是：
- 可用性判断
- 静止条件下心率趋势判断
- 简化 HRV 趋势判断
不要一上来追求和指部一样的质量。

4. 主动指部 PPG 检测流程建议优先承担“报告输出”的职责，因为它更有机会得到高质量信号。

5. 状态机实现时应避免在 `src/main.cpp` 中继续堆实验式逻辑，建议新建一个新的主线集成入口目录，对应新的 PlatformIO env。

## 11. 推荐下一步动作
1. 进入下一步：补齐“完整版主线状态机开发要求 + 新 env 入口规划”。
2. 在实现前先定义 `chest_ppg_profile` 与 `finger_ppg_profile` 的参数结构。
3. 第一阶段代码建议只先跑通 `BOOT -> CALIBRATION_IMU -> MONITOR_PASSIVE -> GUIDED_BREATHING`。

## 12. 本轮已确认约束摘要
- 同一颗 MAX30102 同时承担胸口被动监测与指部主动检测，但两者必须使用不同参数组与不同状态流程。
- 指部主动检测默认用户已把手指紧贴在反射式 PPG 模块上，当前不额外做复杂交互确认。
- 第一版完整版主线暂不并入 AD8232，避免过早增加 ECG 结构和状态复杂度。
