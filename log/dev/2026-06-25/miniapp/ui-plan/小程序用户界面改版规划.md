# 小程序用户界面改版规划

## 头部信息
- 日期：2026-06-25
- 所属模块：微信小程序 / BLE / 云函数 / 云数据库 / 用户界面改版
- 文档用途：在保留当前 BLE 调试界面的前提下，规划一套更适合真实用户使用的小程序界面与数据链路改造方案

## 1. 本次规划结论

当前小程序代码仍处于“链路打通调试页”阶段，不适合直接扩展成最终用户界面。

最合适的改法不是在现有 [web/pages/index/index.js](web/pages/index/index.js) 上继续堆页面逻辑，而是：

1. 保留当前调试页，作为独立 debug 页面长期存在。
2. 新增一个面向用户的首页，首页只保留三个简洁板块入口。
3. 新增主动检测历史页、单次报告页、当日分析页。
4. 云端从“按钮事件测试模型”升级为“检测记录 / 日分析 / 综合建议”三类数据模型。

也就是说，这次改版本质上不是“改现有页面样式”，而是：

1. 保留调试链路不动。
2. 另起一层用户态页面路由。
3. 给用户态页面补真实的数据模型和查询接口。

## 2. 当前现状检查

### 2.1 当前前端现状

当前小程序只有一个页面：

- [web/app.json](web/app.json)
- [web/pages/index/index.js](web/pages/index/index.js)
- [web/pages/index/index.wxml](web/pages/index/index.wxml)

当前这个页面的职责明确是：

1. 扫描 BLE。
2. 连接设备。
3. 订阅按钮事件。
4. 把按钮事件送到云函数。
5. 把云函数返回文本直接显示出来。

它现在更像“BLE 链路打通控制台”，而不是面向用户的健康应用首页。

### 2.2 当前云端现状

当前唯一云函数是：

- [web/cloudfunctions/link_test_ingest/index.js](web/cloudfunctions/link_test_ingest/index.js)

它当前写入的是测试集合 `link_test_events`，并生成的是“按钮事件确认文本”。

因此当前云端数据模型的特点是：

1. 面向按钮测试。
2. 没有主动检测记录模型。
3. 没有日报模型。
4. 没有用户态综合建议模型。

### 2.3 与既有方案文档的一致性

既有直连方案文档已经给出更合理的数据模型方向，见：

- [log/dev/2026-06-17/miniapp/direct-ble-plan/小程序直连硬件开发文档.md](log/dev/2026-06-17/miniapp/direct-ble-plan/小程序直连硬件开发文档.md)

其中已建议：

1. `device_sessions`
2. `vital_stream_summary`
3. `active_measurements`
4. `reports`

这与本次用户界面改版方向是兼容的，不需要推翻已有路线。

## 3. 用户界面目标

你当前想要的用户态界面可以收敛成一个非常清晰的结构：

### 3.1 首页只保留三个板块

首页不再承担 BLE 调试细节展示，而是只保留三个用户板块：

1. 主动检测
   - 展示最近一次指部 PPG 检测结果摘要
   - 可进入历史列表
   - 可进入单次报告详情

2. 当日呼吸与心跳分析
   - 以“天”为单位展示当日呼吸/心率摘要
   - 可以查看不同日期
   - 可以从详情返回首页

3. 近期综合考量与建议
   - 首页直接展示一段综合建议文本
   - 不需要点击进入新页面
   - 由近期测量数据和基础分析结果喂给大模型后生成

### 3.2 调试页独立保留

当前调试页不能删除，建议保留为独立页面，例如：

1. `pages/debug-link/index`
2. 或 `pages/lab/debug/index`

原因：

1. 之后 BLE 联调仍然会长期需要这个页面。
2. 不应把调试状态、特征 UUID、原始事件文本暴露在用户首页。
3. 保留独立调试页能降低后续改用户 UI 时把链路调试能力一起改坏的风险。

## 4. 推荐页面结构

建议把页面结构改成下面这套：

### 4.1 页面路由建议

1. `pages/home/index`
   - 用户主首页

2. `pages/active-history/index`
   - 主动检测历史列表页

3. `pages/active-report/index`
   - 单次主动检测报告页
   - 通过 `measurement_id` 进入

4. `pages/daily-analysis/index`
   - 当日呼吸与心跳分析页
   - 支持日期切换

5. `pages/debug-link/index`
   - 当前 BLE 调试页迁移到这里

### 4.2 首页信息结构建议

首页只展示三张卡片，不展示 BLE 状态、不展示 UUID、不展示原始 JSON。

建议结构：

1. 主动检测卡片
   - 最近一次检测时间
   - 最近一次检测结论短句
   - 最近一次关键参数摘要
   - “查看历史”按钮

2. 当日分析卡片
   - 当日平均呼吸率
   - 当日平均心率
   - 当日异常次数或波动提示
   - “查看详情”按钮

3. 综合建议卡片
   - 直接显示 1 段 2 到 4 行的综合建议文本
   - 不需要按钮

## 5. 推荐数据模型映射

基于既有方案文档，建议把这次用户态页面对应到以下集合：

### 5.1 主动检测相关

集合建议：

1. `active_measurements`
   - 保存一次指部 PPG 主动检测的元信息和结果摘要

2. `reports`
   - 保存单次主动检测的详细报告文本与结构化结果

首页“主动检测卡片”和“历史列表页”主要读这两类数据。

### 5.2 当日分析相关

集合建议：

1. `vital_stream_summary`
   - 保存节流后的呼吸率、心率、信号质量等摘要流

2. 新增 `daily_analysis_snapshots` 或复用 `reports`
   - 如果当天分析需要缓存成文档，建议单独存一份日级快照

“当日呼吸与心跳分析页”应优先基于摘要流聚合，而不是实时现算所有原始数据。

### 5.3 综合建议相关

集合建议：

1. 新增 `insight_cards`
   - 保存近期综合建议文本
   - 带有生成时间和覆盖数据范围

或者：

2. 继续复用 `reports`
   - `report_type = recent_overview`

从实现简洁性看，首版建议直接复用 `reports`，避免一开始新增过多集合。

## 6. 推荐云函数改造

当前只有 `link_test_ingest` 明显不够支撑用户页。

建议新增或拆分成以下职责：

### 6.1 保留现有调试链路

1. `link_test_ingest`
   - 继续保留
   - 仅服务调试页和按钮测试闭环

### 6.2 用户态需要新增的云函数

1. `get_home_overview`
   - 返回首页三张卡所需的聚合数据
   - 包括最近一次主动检测摘要、当日分析摘要、近期综合建议

2. `list_active_measurements`
   - 返回主动检测历史列表

3. `get_active_report`
   - 根据 `measurement_id` 返回单次主动检测详细报告

4. `get_daily_analysis`
   - 根据日期返回日级呼吸与心率摘要

5. `generate_recent_overview`
   - 读取最近几天的检测记录与日分析
   - 拼 prompt
   - 调用大模型
   - 写回综合建议文本

## 7. 需要改哪些前端文件

如果按“保留调试页 + 新增用户页”路线，前端最小改动面大致是：

### 7.1 路由层

1. 修改 [web/app.json](web/app.json)
   - 新增 4 到 5 个页面路由
   - 让首页指向新的用户页
   - 把当前 `pages/index/index` 迁移为 debug 页

### 7.2 调试页迁移

2. 迁移当前：
   - [web/pages/index/index.js](web/pages/index/index.js)
   - [web/pages/index/index.wxml](web/pages/index/index.wxml)
   - [web/pages/index/index.wxss](web/pages/index/index.wxss)

到新的 debug 页面目录。

### 7.3 用户态新增页面

3. 新增：
   - `pages/home/`
   - `pages/active-history/`
   - `pages/active-report/`
   - `pages/daily-analysis/`

### 7.4 数据访问层

4. 新增轻量数据访问封装，例如：
   - `web/utils/cloud-api.js`
   - `web/utils/formatters.js`

这样首页和历史页不需要直接在页面里写很多 `wx.cloud.callFunction` 细节。

## 8. 这次不建议怎么做

以下做法不建议采用：

1. 不建议直接在当前 `pages/index` 上继续叠加用户页 UI。
   - 原因：当前页承载 BLE 扫描连接、通知订阅和按钮事件调试，职责过重。

2. 不建议首版就在用户首页做太多实时 BLE 状态显示。
   - 原因：用户首页应更像“结果入口”，不是调试控制台。

3. 不建议首页就直接展示大段原始参数表。
   - 原因：对真实用户价值低，且会显著破坏简洁界面。

4. 不建议让大模型在前端直接汇总。
   - 原因：模型密钥、聚合口径和结果审查都应保留在云函数侧。

## 9. 建议的最小落地顺序

建议按下面顺序做，而不是同时改所有层：

### 第一步：页面拆层

目标：

1. 把现有调试页迁走。
2. 新建用户首页和 3 个用户页空壳。
3. 先把页面返回关系和导航跑通。

验收：

1. 调试页仍能独立使用。
2. 用户首页只有三个板块入口。
3. 各用户页可正常进出。

### 第二步：先接主动检测历史

目标：

1. 优先接通主动检测历史和单次报告页。
2. 因为这一块最接近你当前“指部 PPG 主动检测”的明确业务。

验收：

1. 首页能显示最近一次主动检测摘要。
2. 历史页能列出历史记录。
3. 点击历史项能进入单次报告页。

### 第三步：接当日分析页

目标：

1. 接入日级呼吸/心率摘要。
2. 支持按天切换。

验收：

1. 至少可查看当天和最近几天摘要。
2. 页面能清楚区分“当天”与“历史日”。

### 第四步：接综合建议卡片

目标：

1. 由云函数汇总近期检测和日分析。
2. 输出一段简短综合建议文本。

验收：

1. 首页第三卡片可稳定展示建议文本。
2. 明确标注是“建议/分析”，不是医学诊断。

## 10. 当前最需要的实际改动清单

如果今天就开始进入实现，最需要做的不是 UI 美化，而是下面这些结构性改动：

1. 改 [web/app.json](web/app.json) 页面路由。
2. 保留当前 BLE 调试页，但迁移到独立 debug 路径。
3. 新增用户首页和 3 个用户页目录。
4. 新增首页聚合云函数 `get_home_overview`。
5. 新增主动检测历史和报告查询云函数。
6. 把当前按钮事件测试集合与后续正式业务集合分开。

其中第 4、5、6 项比页面样式更关键，因为没有这些，用户页就只能展示假数据或临时拼数据。

## 11. 待确认事项

当前仍有几项需要后续明确，但不影响先做页面拆层：

1. 主动检测结果是否一开始只保留“指部 PPG”，还是后续要并入胸口数据入口。
2. 当日分析页是展示“规则聚合结果”还是“云函数 + 大模型总结后的摘要”。
3. 首页综合建议多久刷新一次：
   - 每次打开首页现算
   - 还是按小时/按日缓存
4. 是否需要在首页保留“进入调试页”的隐藏入口。

## 12. 本次建议总括

本次小程序改版建议可以压缩成一句话：

保留现有 BLE 调试页不动，新增一套独立的用户态首页与历史/日报/综合建议页面，并同步把云端从“按钮事件测试模型”升级到“主动检测记录 + 日级分析 + 综合建议”三类数据模型。

这条路线的优点是：

1. 不会破坏当前调试链路。
2. 页面职责清晰。
3. 后续扩展到真实用户数据时不需要重做一次路由结构。
