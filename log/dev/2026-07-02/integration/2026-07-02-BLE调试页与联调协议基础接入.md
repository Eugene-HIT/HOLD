## 主要变更
1. 固件侧补充 `respRateBpm` 到呼吸快照，并新增 `ActivePpgRealtimeSnapshot`，用于主动检测期间实时输出最新处理点、心率、beat 数和接触状态。
2. `data_packager` 新增统一 JSON 协议打包，明确 `msg_type`，覆盖：
   - `device_state`
   - `calibration_status`
   - `resp_debug`
   - `active_realtime`
   - `passive_resp_window`
   - `active_window`
   - `error_status`
3. `ble_link_manager` 的串口占位输出改为直接打印上述 JSON，后续真实 BLE GATT 通道可直接复用同一消息体。
4. 整机入口新增两条周期调试流：
   - 校准/被动监测阶段的 `resp_debug`
   - 主动检测阶段的 `active_realtime`
5. 小程序调试页从“按钮链路测试页”升级为“BLE 调试联调台”，增加：
   - 设备状态窗口
   - 呼吸 bpm / 心率 bpm / motion / quality / beat count 指标窗口
   - 呼吸曲线窗口
   - 心率曲线窗口
   - 调试日志 / 报错窗口
   - 最近原始消息窗口
6. 新增 `web/utils/ble-debug-protocol.js`，统一 BLE 常量、通知解析、设备筛选与演示数据构造。

## 实现思路
- 现阶段真实 ESP32 BLE GATT 服务尚未落地，因此先把“协议字段”和“小程序调试页面”对齐，避免后续 BLE 传输接入时同时改 UI 和协议。
- 呼吸调试流与主动心率调试流按“单点实时更新 + 页面本地缓存窗口”的方式设计，接近 VOFA 的实时观察习惯，但不要求 BLE 侧一次发送整段大数组。
- 小程序调试页保留旧按钮事件兼容解析，避免旧链路验证能力被完全丢掉。
