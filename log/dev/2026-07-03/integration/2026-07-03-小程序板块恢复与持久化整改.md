## 主要问题与结论
1. 首页按钮区存在重复渲染，且“删除所有数据缓存”按钮与三列栅格共同作用，会把首屏布局拉得过宽。
2. 首页多个板块使用 `wx:if` 直接按“有无数据”隐藏，导致用户看到的效果是“板块没了”，与设计文档中板块常驻、空态展示的要求不一致。
3. 主动报告、日分析等数据此前主要存活于小程序运行期内存，页面切换、断连或缓存清理后很容易被误认为“内容消失”。
4. 现有页面体系缺少设计文档要求的整体分析/总结页。
5. 调试页进入后用户感知上的“断连”高度相关于高频波形 + 高频日志同步刷新造成的页面压力，因此本轮同时对调试页数据面做了减压处理。

## 主要变更
1. 首页删除重复按钮区，并对“删除所有数据缓存”按钮增加可换行和收缩约束，避免把布局撑宽。
2. 首页恢复为“板块常驻 + 空态文案”模式，不再因为暂无数据就把整个主动报告、被动报告或总结板块隐藏掉。
3. BLE runtime 新增本地持久化：
   - 主动检测记录
   - 日级分析记录
   - 最近窗口摘要
   - 整体分析摘要
4. 主动报告页补回简要分析、建议和多板块内容，日分析页补回时段记录、摘要与建议。
5. 新增整体分析页 `pages/overall-analysis/index`，承接设计文档中的“总结板块”。
6. 新增云函数 `health_insight`，复用现有 OpenAI 兼容调用方式，为小程序生成简要分析与建议；若未配置密钥则自动回退为本地保守摘要。
7. 调试页链路侧保留批量波形，但去掉批量实时包逐包写日志的高频压力源，降低进入调试页后的主线程负载。

## 实现思路
- 本轮不是继续在首页堆条件渲染，而是先把运行时数据面修正为“内存态 + 本地持久化 + 简要分析摘要”三层。
- 板块恢复遵循设计文档：
  - 指部 PPG 报告
  - 呼吸报告
  - 当天心率报告
  - 总结板块
- 即使暂无数据，也保留页面与区块，只显示明确空态，不再让用户误以为功能被删减。

## 待确认事项
1. 当前“简要分析与建议”已支持云函数调用，但要获得真正的大模型结果，仍需在云函数环境配置 `LLM_API_KEY` 与 `LLM_BASE_URL`。
