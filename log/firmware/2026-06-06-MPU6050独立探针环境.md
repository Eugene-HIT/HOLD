# 2026-06-06 MPU6050 独立探针环境

## 任务名称
为新的 XIAO ESP32S3 Plus + MPU6050 模块建立独立测试入口，验证模块是否可识别并读取原始数据。

## 修改文件
- [platformio.ini](platformio.ini)
- [src/mpu6050_xiao_esp32s3_probe/main.cpp](src/mpu6050_xiao_esp32s3_probe/main.cpp)

## 主要变更
- 在 PlatformIO 中新增 `mpu6050_xiao_esp32s3_probe` 独立环境。
- 新建 MPU6050 独立探针程序，执行以下最小验证：
  - I2C 地址探测 `0x68` / `0x69`
  - `WHO_AM_I` 读取
  - `PWR_MGMT_1` 唤醒写入
  - accel / gyro / temp 原始数据循环打印
- 2026-06-28 补充兼容诊断：放宽 `WHO_AM_I` 判定，支持常见 `MPU6500 / MPU9250 / MPU9255`，并打印 `0x68/0x69` 地址是否 ACK，便于用户更换新模块后快速确认真实芯片族。
- 通过独立入口避免影响现有反射光、EDA、麦克风和 MR60BHA2 测试代码。

## 实现思路
- 沿用现有 MR60BHA2 独立 env 的隔离方式，不在主线 [src/main.cpp](src/main.cpp) 内切换逻辑。
- 采用原始寄存器访问而不是额外第三方库，降低首次验证的不确定性。
- 优先判断“模块是否活着、地址是否正确、数据是否能读”，不在本阶段加入姿态解算或呼吸算法。

## 接线约定
- XIAO 3V3 -> MPU6050 VCC
- XIAO GND -> MPU6050 GND
- XIAO D4(GPIO5) -> MPU6050 SDA
- XIAO D5(GPIO6) -> MPU6050 SCL
- MPU6050 AD0/ADC -> GND
- MPU6050 INT/XDA/XCL 先不接

## 验证目标
- 上电后串口应输出接线提示、I2C 引脚信息和探测结果。
- 若模块正常，应看到 `0x68/0x69` 的 ACK 状态、识别出的 `model=...`、`WHO_AM_I=...` 和持续更新的原始加速度/陀螺仪数据。
- 若只看到 `no valid device found`，优先排查接线、电源、AD0 地址脚，以及新模块是否属于完全不同的芯片系列。

## 待确认事项
- 用户手头模块丝印 `ADC` 是否确认为 `AD0`。
- 后续是否需要把 INT 引脚接入，用于数据就绪中断验证。
- 如果该模块验证通过，下一步是先做原始稳定性观察还是直接做胸口贴附日志实验。

## 下一步建议
1. 先编译并烧录 `mpu6050_xiao_esp32s3_probe`。
2. 观察串口中是否稳定输出 `WHO_AM_I` 与原始数据。
3. 若能读到数据，再进入胸口静止/走动对比实验。
