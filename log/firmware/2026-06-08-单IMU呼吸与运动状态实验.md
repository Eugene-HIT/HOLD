# 2026-06-08 单 IMU 呼吸与运动状态实验

## 任务名称
基于单颗 MPU6050 建立胸口贴附场景下的呼吸节律与运动状态实验入口。

## 主要变更
- 新增独立 env：`mpu6050_xiao_esp32s3_respiration`
- 保留原始探针环境 `mpu6050_xiao_esp32s3_probe` 不变
- 新增单 IMU 实验程序，输出：
  - `motion_level`
  - `breath_interval_s`
  - `breath_rate_bpm`
  - `inhale_s`
  - `exhale_s`
  - `sigh_count`
  - 辅助工程量：`acc_norm_g`、`gyro_norm_dps`、`pitch_deg`、`roll_deg`

## 实现思路
- 延续前期调研中“单 IMU + 运动门控 + 基础呼吸周期提取”的最小闭环。
- 使用加速度重力方向估计呼吸主轴上的微小起伏，再做基线漂移去除和平滑。
- 使用角速度与动态加速度范数进行运动等级分类。
- 使用波峰/波谷交替检测近似估计吸气时间、呼气时间和完整呼吸周期。
- 用相对平均值的长呼气、长周期和较大振幅联合条件统计长叹气次数。

## 当前算法边界
- 更适合静止或轻微运动场景。
- 剧烈运动场景下，`motion_level=vigorous` 时呼吸事件更新会明显减少，结果仅作参考。
- 吸气/呼气时间为工程估计值，不是医学级呼吸相位标注。
- 长叹气判定当前采用阈值法，后续应结合真实日志再调参。

## 建议验证顺序
1. 先胸口贴附静坐，观察是否出现稳定 `breath_interval_s` 和 `breath_rate_bpm`
2. 再轻微转身、说话、走两步，观察 `motion_level` 是否提升
3. 再刻意做一次较长呼气或长叹气，观察 `sigh_count` 是否增加
4. 最后再与 MR60BHA2 并排观察一致性

## 待确认事项
- 当前贴附方向下，呼吸信号是否在现有重力投影方案中足够明显
- `motion_level` 阈值是否需要按实际胸前佩戴方式重新标定
- 长叹气阈值是否需要针对用户实际呼吸习惯调整

## 下一步建议

- 结论：上一版不是“没有信号”，而是时间窗收紧过度，导致所有候选都被 `trough_half_short / peak_half_short` 挡掉。
- 当前已将最小半周期回调到 `750ms`、最小整周期回调到 `1800ms`，保留其余去抖与锁定逻辑不变，以恢复可观测性后再继续调参。

- 最新反馈显示：在 `700ms / 1700ms` 组合下，当前佩戴方式仍会出现“过严到基本无有效周期”的回归现象。
- 因此再次做最小回调：最小半周期调整为 `650ms`，最小整周期调整为 `1500ms`，其余状态机、去抖、锁定和叹气逻辑保持不变。
- 当前目标不是追求最终最优，而是先把有效周期恢复到“稳定可观察”的区间，再基于串口继续收敛误检率。
- 用户进一步反馈：当前版本附近已较稳定，但仍略偏严格，且 `breath_interval_s / breath_rate_bpm` 看起来像“板子时间不准”。
- 复核结论：问题不在 MCU 计时本身，而在显示策略此前直接使用了“累计平均周期”，导致当前呼吸间隔与频率显示发黏、滞后，不像实时值。
- 本轮已将“最新一次有效周期”与“历史平均周期”拆开保存：
  - `breath_interval_s / breath_rate_bpm / inhale_s / exhale_s / breath_amplitude_g` 改为显示最近一次有效周期
  - `avg_interval_s / avg_inhale_s / avg_exhale_s` 继续显示平均值
- 同时仅做一档轻微放松：最小半周期改为 `620ms`，最小整周期改为 `1450ms`，继续围绕当前稳定版本细调而不重写状态机。
- 随后串口进一步表明：在有效周期长时间未更新时，当前周期字段仍会持续显示旧值，使人误以为呼吸间隔计算或板载时钟异常。
- 本轮已增加“当前周期过期失效”策略：若最近一次有效周期超过 `6s` 未更新，则 `breath_interval_s / breath_rate_bpm / inhale_s / exhale_s / breath_amplitude_g` 自动回到无效显示，避免旧值长时间挂屏。
- 同时再轻微放松一档：最小半周期改为 `600ms`，最小整周期改为 `1400ms`，接受后锁定时间从 `1200ms` 调整到 `1000ms`，以改善当前版本“略严格”的问题。
- 用户继续反馈：当前现象表现为“正常呼吸偏难触发、剧烈运动反而容易触发、深呼吸可能一口多记、偶尔准确但连续几次后又漂掉”。
- 本轮判断不再只归因于单个阈值，而是认为固定 `1000ms` 接受后锁定过于僵硬：对慢而深的呼吸不够抑制重复计数，对较弱的正常呼吸又缺少自适应余量。
- 因此改为“按上一轮有效周期长度比例锁定”：
  - 锁定时长 = `上一轮周期 * 0.65`
  - 最小 `900ms`，最大 `2200ms`
- 同时再轻微放松当前版本：最小半周期改为 `560ms`，最小整周期改为 `1300ms`。目标是让正常呼吸更容易通过，同时减少深呼吸和体动的一口多记。

  - 用户提供 VOFA 截图后，当前问题已不再是“看不到呼吸主波”。从曲线看，`breath_filtered_g` 已存在明显缓慢起伏，但其上叠加了较明显的高频毛刺。

  - 这也与前面多轮日志中的症状一致：`detected_peaks / detected_troughs` 增长很快，但后续大量卡在 `peak_half_short / trough_half_short / interval_out_of_range`。

    - 斜率翻转时，不再无条件认定为峰或谷

  - 本轮目的不是直接彻底定型状态机，而是先让极值计数从“每秒十几个”回到更接近真实呼吸节律的量级，再继续看是否还剩下时间窗或门限问题。
