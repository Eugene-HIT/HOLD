# 2026-07-03 主动PPG检测断连与报告失败修复

## 任务名称
缓解 1 分钟指部 PPG 主动检测期间的 BLE 断连风险，并补齐主动报告页的真实报告生成与失败原因展示

## 修改文件
- include/integration_types.h
- src/integration/ble_link_manager.cpp
- web/cloudfunctions/health_insight/index.js
- web/utils/hold-ble-runtime.js
- web/pages/active-report/index.js
- web/pages/active-report/index.wxml
- web/pages/active-report/index.wxss

## 主要变更
- 将 kActiveRealtimeBatchCapacity 从 5 提升到 10，把主动检测实时包从约 20 次/秒降到约 10 次/秒，在不丢点的前提下降低 BLE notify 压力
- 将主动/被动 PPG 高频日志从“整包 payload 打印”改为简短摘要行，减少串口输出对主循环与 BLE 链路的干扰
- 云函数 health_insight 增加 report_kind 支持，针对 active_report / daily_report 返回更贴近场景的 fallback 文本
- 运行时为 activeMeasurements 增加 generatedReportText / Source / Error / UpdatedAt 字段
- 新增 requestActiveMeasurementInsight()，由小程序主动报告页直接调用云函数，并把 source 与 error_message 写回缓存
- 主动报告页新增“生成报告”按钮、结果来源展示、错误原因展示

## 本次判断与结论
本次优先按两个最可能的根因收口：
1. 主动检测实时包过于频繁，叠加串口刷屏，容易让蓝牙链路在 1 分钟持续流阶段变脆弱
2. 主动报告页原先并没有真正的云函数调用链，因此用户看到“报告失败”时无法区分是模型没配、调用报错，还是页面根本没发起请求

本轮改动后：
- 主动检测 BLE 负载已下降
- 主动报告页已经具备真实生成能力
- 若模型未调用成功，小程序会直接显示 source 与 error_message，便于继续定位

## 待确认事项
1. 需要真机确认主动检测 60 秒过程中 BLE 是否仍容易断连
2. 需要真机点击主动报告页“生成报告”，观察 source 是 llm 还是 fallback
3. 若仍出现 fallback，需要根据 error_message 进一步判断是 LLM_API_KEY / LLM_BASE_URL 缺失，还是上游模型接口返回异常

## 下一步建议
1. 真机先完成一次 60 秒指部检测，观察检测中和检测结束后的 BLE 稳定性
2. 进入主动报告页点击生成报告，记录 source 与 error_message
3. 若 BLE 仍偶发断连，可继续把主动实时包改为 15 或 20 点一包，或给主动检测页单独降采样显示
