# 2026-07-03 呼吸BPM与跳点缺失修复

## 任务名称
修复整机呼吸曲线已有但呼吸 BPM 与检测跳点缺失的问题，并对齐独立呼吸测试工程的核心检测口径

## 修改文件
- src/integration/resp_calibration_manager.cpp

## 主要变更
- 修正整机呼吸检测中 acceptTrough 的关键时序判断错误
- 将整机版呼吸周期接受逻辑改为与独立呼吸工程同向的“谷到谷”周期计算，而不是错误地卡在峰谷先后判断上
- 为整机版补入与独立工程一致方向的基础门限：
  - kRespMinHalfBreathMs = 560
  - kRespMinBreathIntervalMs = 1300
  - kRespMaxBreathIntervalMs = 10000
- acceptPeak / acceptTrough 现在都支持“重复峰/重复谷仅更新极值并等待另一侧极值”的处理方式，避免单边极值连发时把检测链打断
- 呼吸 BPM 现在基于 trough-to-trough interval 计算，并将 lastAcceptedCycleAtMs 改为记录 trough 时刻，和独立呼吸工程方向一致
- 呼吸跳点脉冲从固定 0.08f 改为相对振幅可见脉冲：max(latestAmplitudeG * 1.8f, 0.08f)
- 增加 stale 规则：超过 kRespDisplayStaleMs 未再接受有效周期时，latestRespRateBpm 归零，避免长期悬挂旧值
- 将 extremum 接受时间偏移统一改为 kRespSampleIntervalMs，替代硬编码 20ms

## 根因判断
本次问题不是前端没画，而是整机算法在 trough 接受路径上有明确逻辑错误：
- 旧代码在 acceptTrough 中使用 if (!hasPeak || lastPeakAtMs <= atMs) return;
- 对正常呼吸时序“先峰后谷”而言，lastPeakAtMs <= atMs 本来就成立
- 这会导致正常 trough 被提前 return，后续 amplitude、interval、respBeatMarkerPending、latestRespRateBpm 都无法成立

因此用户看到的现象就是：
- 呼吸曲线有
- 但 BPM 一直没有
- 也看不到检测到呼吸时的跳点

## 与独立呼吸工程的对齐结论
本轮已将整机版的核心接受方向对齐到 [src/mpu6050_xiao_esp32s3_respiration/main.cpp](src/mpu6050_xiao_esp32s3_respiration/main.cpp) 的以下关键原则：
- 峰谷检测仍基于同样的 baseline / smooth / detection low-pass 三层滤波
- 周期接受以 trough-to-trough 为主
- 需要满足最小半周期门限
- 需要满足最小/最大整周期门限
- 重复峰/重复谷先更新极值，等待另一侧极值闭环
- 显示时按 stale 规则决定是否继续显示有效呼吸率

当前整机版仍然是独立工程的简化实现，没有完整搬入独立工程中的：
- motion level 分级门控
- acceptance lock
- inhale / exhale 平均值与 ratio
- sigh 统计

但针对“为什么没有 BPM / 为什么没有跳点”这一问题，关键控制链已经恢复到与独立工程一致的方向。
