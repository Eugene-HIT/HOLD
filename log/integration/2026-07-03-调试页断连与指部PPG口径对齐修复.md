# 2026-07-03 调试页断连与指部PPG口径对齐修复

## 任务名称
缓解进入调试页后容易断连的问题，并收敛整机指部 PPG 与独立 finger VOFA 工程之间的关键运行差异

## 修改文件
- include/resp_calibration_manager.h
- src/integration/resp_calibration_manager.cpp
- src/xiao_esp32s3_integrated_hold/main.cpp
- web/pages/index/index.js

## 主要变更
- 扩展 respCalibrationManagerTick 接口，新增 runtimeMonitoringEnabled 参数
- 整机主循环在主动指部检测期间，暂停呼吸 IMU 的运行时采样，只在呼吸校准 / 被动监测 / 呼吸引导阶段继续采样
- 调试页改为节流消费 runtime 状态，不再每个 BLE 包都立即 setData 和触发双 canvas 重绘
- 调试页日志列表改为只保留前 12 条显示，进一步降低页面刷新压力
- 调试页 chart redraw 节拍从 33ms 对齐到统一的 120ms 渲染节拍

## 对比结论
本轮对比 [src/max30102_xiao_esp32s3_vofa/main.cpp](src/max30102_xiao_esp32s3_vofa/main.cpp) 与 [src/integration/active_test_manager.cpp](src/integration/active_test_manager.cpp) 后，结论不是“手指算法参数不同”，而是：

### 已确认一致的部分
- HeartRateEstimator 使用的都是 defaultFingerProfile
- 指部显示链都是：
  - dcAlpha = project_config::kHeartRateDcAlpha
  - signalAlpha = project_config::kHeartRateSignalAlpha
  - display gain = project_config::kMax30102VofaFilteredDisplayGain
- beat marker 都是使用 filtered display point 作为可见脉冲

### 已确认不一致且会影响效果的部分
- 独立 finger 工程运行时只有 MAX30102 一条主链
- 整机主动检测时，之前即便不在呼吸页面，respCalibrationManager 仍会持续读 MPU6050
- MPU6050 与 MAX30102 共用同一条 I2C，总线竞争会直接让主动指部 PPG 的稳定性和波形效果偏离独立 finger 工程
- 调试页原先每个 BLE 包都 setData + 双 canvas 重绘，更容易在进入页面后造成小程序端卡顿与断连感知

因此本轮先修正“运行环境差异”和“前端渲染压力”，而不是先动 finger 心率算法参数本体。
