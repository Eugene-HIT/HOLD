# 2026-07-04 主动PPG整窗分片退场与实时累计主路径修正

## 任务名称
修复指部 PPG 主动检测“1/32 卡死、详情页现象无变化、报告生成与显示口径脱节”的根因链

## 修改文件
- src/xiao_esp32s3_integrated_hold/main.cpp
- web/utils/hold-ble-runtime.js
- web/pages/active-report/index.js
- web/pages/active-report/index.wxml

## 主要变更
- 固件侧停止发送主动检测完整窗口的 32 片 JSON 分片，改为仅发送一条 active_window 元数据包
- 主动检测整分钟波形与 beat 统一改为由 active_realtime_batch 持续累计，不再依赖 active_window 的 processed_points_fragment / beat_ts_ms_fragment 收齐
- 前端主动记录完成条件改为“实时累计点数/时长达到整分钟”优先，而不是等待整窗分片收全
- 详情页新增更明确的本地反馈文案，显示当前记录来源、实时累计点数、窗口分片状态和生成报告反馈

## 本次判断与结论
本次把问题控制路径重新收敛后，根因更明确：
1. 用户持续看到 1/32，说明主动整窗分片在微信 BLE 上并未稳定送达
2. 前端虽然尝试用 realtime batch 绕过，但仍保留了对 active_window 收齐的隐性依赖，因此用户体感上“和之前一模一样”
3. 只要固件继续瞬发 32 片 active_window，微信侧就会反复暴露同样的不稳定现象，因此应直接让该链路退场

结论：
- active_window 只保留元数据职责
- active_realtime_batch 成为主动检测唯一主波形来源
- 后续若还要传完整 60 秒窗口，只能考虑更紧凑协议或离线拉取，不应继续堆长 JSON 分片
