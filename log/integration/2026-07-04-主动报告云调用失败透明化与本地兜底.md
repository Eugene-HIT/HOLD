# 2026-07-04 主动报告云调用失败透明化与本地兜底

## 任务名称
修复指部 PPG 详情页点击“生成这次报告”后直接提示失败、无法判断失败层级的问题

## 修改文件
- web/utils/hold-ble-runtime.js
- web/pages/active-report/index.js

## 主要变更
- 在主动报告生成链中增加本地兜底报告生成函数
- 当 wx.cloud 不可用或 wx.cloud.callFunction 调用直接抛错时，不再只返回失败，而是写回一份本地兜底报告
- 本地兜底报告会明确写出：当前心率、beat 数、缓存点数、记录来源以及云调用失败原因
- 详情页在云端失败但本地兜底成功时，提示改为“已切本地兜底”，不再单纯显示“生成失败”
- 主动报告失败原因同步写入 runtime 调试日志，便于后续在小程序调试页继续排查

## 本次判断与结论
从当前代码路径看，“点生成报告立刻失败”并不表示模型内容有问题，而更像 wx.cloud.callFunction 这一层没有真正打通。

为避免用户始终停留在“失败但不知道为什么”的状态，本次先把失败链改成两段：
1. 云端能打通时，继续返回真实云端报告或 fallback 结果
2. 云端调用层直接失败时，页面仍生成一份本地兜底报告，并明确展示失败原因

这样做的好处是：
- 用户不再面对空白失败
- 可以直接从页面或调试日志看到失败是 cloud 不可用、调用异常，还是云函数侧 fallback
