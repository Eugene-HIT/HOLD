# 2026-07-04 胸口PPG显示抽样与报告失败透明化修复

## 任务名称
修复胸口 PPG 曲线长期观看仍容易掉线的问题，并取消报告页对“数据量不足”的前端拦截，同时把失败原因透明化展示

## 主要变更
- 日报页新增节流状态刷新，避免每次 runtime 更新都立即 setData
- 日报页绘图改为“缓存保留，显示抽样”：
  - 呼吸曲线显示抽样 240 点
  - 呼吸跳点显示抽样 240 点，按绝对值保峰
  - 胸口 PPG 曲线显示抽样 360 点
  - 胸口 PPG 跳点显示抽样 360 点，按绝对值保峰
- 胸口 PPG 原始缓存仍然保留在 runtime 中，不再因为页面渲染优化而丢掉 1 分钟缓存本身
- 日报页生成报告不再以“窗口数不足”为前端拦截条件，而是始终把当前已有数据发给模型
- prompt 已明确要求：若数据不足，由模型在正文里说明不足，不允许拒绝回答
- 日报页现在展示：
  - reportSource
  - reportError
  - reportUpdatedAt
- 整体分析页“生成详尽报告”同样改为始终发请求，并展示来源和错误原因
- 云函数 health_insight 现在明确区分：
  - invalid-request：prompt 为空
  - fallback-config-missing：缺 LLM_API_KEY 或 LLM_BASE_URL
  - fallback-llm-error：已发到模型接口，但接口调用失败或未返回有效内容
  - llm：模型正常返回
- 去掉了此前 fallback 文案里“建议继续积累更多窗口后再次生成”这类替模型做判断的提示

## 本次判断与结论
本次问题有两个不同层面的根因：
1. 胸口 PPG 不是缓存没截断，而是页面一直拿全量长缓存参与绘图，导致持续观看时小程序端渲染压力偏大
2. 报告失败并不总是“模型真的失败”，此前页面和云函数混用了过于模糊的 fallback 文案，用户无法区分是配置缺失、接口失败，还是仅仅走了 fallback

因此本轮没有缩短缓存，而是：
- 保留缓存长度
- 缩短显示长度
- 保留峰值可见性
- 明确错误来源

- 日报页图表随后进一步从“全缓存压缩显示”改为“尾部滑动窗口显示”

  - 现在胸口 PPG 也显示最近 240 点

- 用户再次上传后，真机截图确认 health_insight 已能被找到，但云端执行失败原因为缺少 wx-server-sdk
- 已为 health_insight 补充 package.json 与 config.json，使其与现有 link_test_ingest 云函数目录结构一致
- 重新上传部署 health_insight 后，云端应会自动安装 wx-server-sdk，之后才会进入 LLM 配置或接口层面的排查

## 指部 PPG 参数放宽试验
- 用户反馈整机中的指部主动检测效果偏差，要求参考胸口路径适度放宽参数
- 本轮没有改全局 defaultFingerProfile，也没有改胸口路径，只在 src/integration/active_test_manager.cpp 局部构造 relaxed finger profile
- 本次放宽内容：
  - presenceIrMeanThreshold: 8000 -> 6000
  - presenceRedMeanThreshold: 2000 -> 1200
  - dcAlpha: 0.05 -> 0.06
  - signalAlpha: 0.20 -> 0.18
  - amplitudeMin: 120 -> 70
  - beatIntervalMinMs: 300 -> 330
  - beatIntervalMaxMs: 2000 -> 2200
  - beatStaleTimeoutMs: 2500 -> 3200
  - contactLossResetMs: 1500 -> 2200
- 目的：降低整机接线、贴合和运行干扰下的“可用波形被判掉”概率，提高主动检测的稳定性
- 验证：PlatformIO 环境 xiao_esp32s3_integrated_hold 编译通过

## 指部主动检测数据链补全
- 用户进一步怀疑小程序端看不到单独指部测试的效果，要求检查是否在链路中随意丢弃数据
- 核查后确认根因不是小程序页面主动抽样，而是 active_window 之前只上传了 heart_rate_bpm、quality_score、processed_point_count、beat_count 等元数据，并没有把完整 60 秒 processedPoints / beatTsMs 上传到小程序
- 结果是：
  - 调试页只能看到短环形 heartWavePoints 缓存
  - 主动检测报告与整体报告只能拿到短尾部缓存，而不是完整 60 秒窗口
- 本轮修复：
  - 固件端 active_window 改为按片发送完整 processedPoints 与 beatTsMs
  - 小程序 runtime 按 measurement_id 重组所有 active_window 分片
  - 分片收齐后再生成 activeMeasurements 记录
  - 主动检测报告与整体报告现在会优先使用完整窗口波形，而不是调试页尾部短缓存
- 验证：
  - web/utils/hold-ble-runtime.js 语法通过
  - xiao_esp32s3_integrated_hold 固件编译通过
