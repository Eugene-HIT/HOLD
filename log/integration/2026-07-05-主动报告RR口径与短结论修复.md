# 2026-07-05 主动报告RR口径与短结论修复

## 任务名称
修复主动检测详情页中总 beat 与 RR 个数口径混淆的问题，并把模型分析输出收紧为只基于有效片段的短结论。

## 修改文件
- web/pages/active-report/index.js
- web/utils/hold-ble-runtime.js
- src/integration/active_test_manager.cpp

## 主要变更
- 详情页新增有效片段统计：区分 `总 beat` 与 `有效 RR 对应 beat`
- 调试文案不再把 `beatTimelineMs.length` 直接当总 beat，而是显示 `beats / effective / rr` 三种口径
- 主动报告 prompt 改为强约束短输出：只谈有效 RR 片段的平稳度、心率快慢与焦虑倾向
- 云端返回文本如果过长，或继续出现“无法判断、数据质量、置信度、干扰因素、复测建议”等说法，则在前端自动压缩成本地短结论
- runtime 备用主动报告 prompt 与本地 fallback 文案同步改成短结论风格
- 固件 `storeBeatTimestamp()` 放宽 RR 记录条件：每次 beat 增加时，只要 `I12` 非零就写入 RR 数组，不再额外要求 `contactPresent` 与 `hasValidBpm`

## 本次判断与结论
- 当前 `38 beat / 31 RR` 不是页面再次吃旧缓存，而是“总 beat”和“有效 RR 片段”口径不同
- 前端此前又把 `beatTimelineMs.length` 当成 beat 数显示在调试里，进一步放大了混淆
- 经过本次修复后，页面会明确显示有效 RR 对应的分析口径，模型输出也会只围绕有效片段给简短偏向性结论
