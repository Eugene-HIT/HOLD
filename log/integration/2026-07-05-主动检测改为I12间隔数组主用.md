# 2026-07-05 主动检测改为I12间隔数组主用

## 任务名称
将 60 秒指部主动检测的 HRV 主输入改为固件侧按 beat 增长采集的 `I12=lastBeatIntervalMs` 间隔数组，前端不再以 beat 时间点重建作为主路径。

## 修改文件
- include/integration_types.h
- src/integration/active_test_manager.cpp
- src/integration/data_packager.cpp
- web/utils/hold-ble-runtime.js
- web/pages/active-report/index.js

## 主要变更
- 固件主动检测实时快照与批量包新增 `I12` 字段，对应 `lastBeatIntervalMs`
- 固件主动检测窗口新增 `rrIntervalCount` 与 `rrIntervalsMs`，在每次 beat 有效增加时，把当前 `I12` 追加进 60 秒数组
- BLE `active_window` 额外携带 `rr_interval_count` 与 `rr_intervals_ms_fragment`
- 前端 runtime 处理 `active_window` 时，优先使用固件直接发送的 `rr_intervals_ms` 作为 HRV 输入
- 详情页 prompt 改为优先围绕心率间隔数组与总 beat 数分析；beat 时间点降级为辅助展示
- 详情页与 runtime 的画图跳点优先保留实时 `I7`，不再让时间线重建抢主位

## 本次判断与结论
- 用户要求已明确收敛为：主动检测真正需要喂给 AI 的是 `I12` 形成的心率间隔数组，`I6` 只画波形，`I7` 只画 beat，`I8` 只显示 bpm
- 因此 HRV 主路径必须前移到固件侧，由固件在 beat 增长时直接存 `I12`，再由前端直接透传
