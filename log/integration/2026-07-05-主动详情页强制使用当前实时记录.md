# 2026-07-05 主动详情页强制使用当前实时记录

## 任务名称
修复指部详情页关键参数和报告生成仍优先使用旧缓存记录，导致 `I8` bpm、beat 数和 AI 输入不跟随当前 60 秒检测更新的问题。

## 修改文件
- web/utils/hold-ble-runtime.js
- web/pages/active-report/index.js

## 主要变更
- runtime 新增 `buildCurrentActiveMeasurementFromLatestWindow()`，专门从最新 `active_window` 与当前实时累计缓存构建当前这次主动检测记录
- `ensureActiveMeasurementFromLatestWindow()` 补充透传 `rr_intervals_ms`，避免当前记录落库时丢失 I12 间隔数组
- 详情页订阅刷新时，优先使用当前实时记录，而不是优先拿 `activeMeasurements[0]` 旧缓存
- 关键参数中的 bpm/beat 因此会跟随当前记录的 `realtime_heart_rate_bpm` / `realtime_beat_count`，对应 `I8` 与固件 beat 计数
- 二次修复：`applyActiveWindow()` 不再用窗口旧 `heart_rate_bpm/beat_count` 反向覆盖实时 `I8/bc`
- 二次修复：`active_realtime_batch` 到达后同步刷新 `latestActiveWindow.realtime_heart_rate_bpm/realtime_beat_count`
- 二次修复：同一条最新测量已落库时，`ensureActiveMeasurementFromLatestWindow()` 会用最新窗口和当前实时值重建，而不是早退返回旧记录
- 二次修复：详情页 fallback metrics 和报告生成入口均优先使用当前 `viewReport` / runtime 实时值
- 页面构建号更新为 `active-report 2026-07-05-09`，用于确认开发者工具/真机运行的是本次二次修复后的页面

## 本次判断与结论
- 用户真机截图显示图形已经更新，但关键参数仍停在旧的 `45 bpm / 32 beat`
- 这说明实时 `I6/I7` 已经进入画图路径，但详情页用于参数和报告的对象仍被旧 `activeMeasurements[0]` 抢占
- 当前修复将“当前最新主动检测”提升为详情页最高优先级，避免旧缓存继续污染关键参数与 AI 输入
