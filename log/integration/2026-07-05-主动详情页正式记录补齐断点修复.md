# 2026-07-05 主动详情页正式记录补齐断点修复

## 任务名称
针对“还没测就有 bpm/beat”与“stored=0 canGenerate=1 但仍生成失败”的现象，精准收敛主动详情页的缓存预览与正式记录补齐断点

## 修改文件
- web/utils/hold-ble-runtime.js
- web/pages/active-report/index.js

## 主要变更
- 新增稳定的主动检测记录 ID 解析逻辑：优先使用 measurement_id，缺失时回退到 sample_start_ts_ms / sample_end_ts_ms 组成的稳定 ID
- 将 pendingActiveRealtimeMeasurements 的 key 解析改为兼容 measurement_id 缺失/为空的稳定字符串
- 详情页 fallback 记录新增 isPreview 标记
- 详情页调试信息新增 preview 标志位，并在 ensureActiveMeasurementFromLatestWindow 失败时直接把“补正式记录失败”打印到页面上
- fallback 预览态下的指标文案改为“最近缓存心率 / 最近缓存 beat 数”，避免冒充当前实时值

## 本次判断与结论
根据用户最新截图：
1. 调试信息显示 stored=0 canGenerate=1
2. 这说明页面知道“这条记录可以生成”，但 report 仍不在 activeMeasurements 里
3. 生成链的最像断点不是模型输入过大，而是 fallback 视图没有成功补成正式记录

因此本次优先处理两个问题：
- 解决 fallback 视图补正式记录时的 ID 不稳定问题
- 明确区分“最近缓存预览”与“当前实时指标”
