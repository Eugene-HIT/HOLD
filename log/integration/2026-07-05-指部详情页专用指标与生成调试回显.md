# 2026-07-05 指部详情页专用指标与生成调试回显

## 任务名称
修复指部 PPG 详情页的 bpm/beat 被全局胸口心率状态污染，以及生成报告失败时缺少硬调试信息的问题

## 修改文件
- web/utils/hold-ble-runtime.js
- web/pages/active-report/index.js
- web/pages/active-report/index.wxml

## 主要变更
- 在 runtime state 中新增 currentActiveHeartBpm / currentActiveBeatCount，专门记录指部主动链的当前心率与 beat 数
- 在 active_realtime / active_realtime_batch / active_window 三处主动链入口同步更新上述专用状态
- 详情页 fallback 报告改为优先使用 currentActiveHeartBpm / currentActiveBeatCount，不再回退到 currentHeartBpm / currentBeatCount 这种可能被胸口 PPG 覆盖的全局值
- 详情页新增 runtimeDebugInfo，将报告生成链上的 stored / canGenerate / ok / reason / source / error 直接显示在页面上

## 本次判断与结论
用户反馈“beat 长时间停在 62 不变，bpm 似乎跟着胸口PPG走”，结合现有 runtime 结构确认：
1. currentHeartBpm / currentBeatCount 是全局心率状态，主动指部链与被动胸口链都会写它
2. 详情页 fallback 逻辑此前读取的是这组全局字段，因此在主动记录尚未完全落成正式 report 时，显示指标可能被胸口链覆盖
3. 要判断“生成失败”是否真是调用错了，还需要把 requestActiveMeasurementInsight 的返回结构直接落到页面，而不是只依赖 toast

结论：
- 指部详情页必须使用主动链专用状态
- 生成报告的运行时调试信息必须直接可见
