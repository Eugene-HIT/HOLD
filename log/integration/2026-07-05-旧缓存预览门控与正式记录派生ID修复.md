# 2026-07-05 旧缓存预览门控与正式记录派生ID修复

## 任务名称
修复“未开始指部检测时详情页仍显示上一次缓存 bpm/beat”以及“preview=1 canGenerate=1 但无法补成正式记录”的问题

## 修改文件
- web/utils/hold-ble-runtime.js
- web/pages/active-report/index.js
- web/pages/home/index.js

## 主要变更
- runtime 的 ensureActiveMeasurementFromLatestWindow() 改为支持稳定派生 ID，而不是只按 measurement_id 硬匹配
- fallback 预览记录 ID 改为稳定派生值：优先 measurement_id，其次 sample_start_ts_ms / sample_end_ts_ms
- 详情页仅在两种情况下允许使用 latestActiveWindow 做预览 fallback：
  1. 显式传入 reportId
  2. 当前设备状态为 FINGER_PPG_ACTIVE_TEST
- 首页“查看详情”入口收紧为：只有已有正式主动记录，或当前确实正在指部主动检测，才允许进入详情页

## 本次判断与结论
用户连续反馈：
1. 没有开始测手指 PPG 也会先看到 bpm/beat
2. 调试信息显示 stored=0 preview=1 canGenerate=1，说明页面拿到的是可生成的预览记录，但没有补成正式记录

本次判断的核心结论是：
- 旧缓存本不应在未开始当前检测时冒充当前详情页内容
- preview 记录无法补成正式记录的根因是 ID 匹配口径不稳定

因此本次分别从“预览展示门控”和“正式记录 ID 派生”两侧收口。
