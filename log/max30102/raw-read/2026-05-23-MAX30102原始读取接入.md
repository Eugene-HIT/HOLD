## 实现思路
- 采用寄存器直连方式，而不是先引入第三方库，目的是把当前问题收敛到 I2C 链路和基础配置层
- 使用 Seeed 官方 XIAO ESP32S3 默认 I2C 引脚 D4(GPIO5/SDA) 与 D5(GPIO6/SCL)
- 使用 MAX30102 常见地址 0x57，并先尝试读取 Part ID(预期 0x15)
- 若初始化失败，则周期性重扫 I2C 总线并持续输出失败原因，避免监视器晚连接时丢失关键诊断信息
- 心率算法先采用最小可运行路线：以 IR 为主通道，做 DC 跟踪去除、指数平滑、零交叉附近的峰值触发，再用最近几个有效心跳间隔平均得到 BPM
- 当前实现参考 GitHub 上常见的 MAX30102 工程思路，但没有直接搬运整段算法代码，便于后续按本工程结构继续演进

## 问题与解决
### 问题一：启动阶段读不到 Part ID
- 现象：`part-id-read-failed`，`part_id=0x0`
- 排查结论：早期阶段 I2C 链路并不稳定，无法稳定完成寄存器访问
- 解决动作：增加 I2C 扫描、周期重扫、初始化失败重试和更详细的错误日志

### 问题二：运行时出现 `fifo-pointer-read-failed`
- 现象：设备有时能识别，但后续读取 FIFO 指针失败
- 排查结论：不能只看是否识别到设备，还要看运行期寄存器访问是否持续成功
- 解决动作：补充最近一次寄存器地址、事务状态、请求字节数、返回字节数和失败计数日志，并将 I2C 时钟降到 100kHz 做稳态排查

### 问题三：`no-sample-yet` 且 `reason=ok`
- 现象：I2C 正常、配置可回读，但 `wr_ptr=0 | rd_ptr=0 | avail=0`
- 排查结论：这说明不是通信失败，而是 FIFO 没有开始累计样本，问题落在初始化兼容性而不是数据解析
- 解决动作：参考成熟库补充 slot 配置寄存器写入，并打开 FIFO rollover；补充关键寄存器回读验证配置是否真的生效

### 最终解决结果
- 加入 slot 配置和兼容性调整后，串口已持续输出递增的 `seq` 与稳定的 `red / ir` 原始值
- 说明当前 MAX30102 原始采样链路已经打通

## 避免再踩坑
1. 不能只看 `Part ID` 是否能读到，必须同时观察运行期是否会出现 FIFO 指针读失败
2. 看到 `reason=ok` 但仍然 `no-sample-yet` 时，不要误判为接线问题，应先检查 `wr_ptr / rd_ptr / avail`
3. 对 MAX30102 这类器件，最小寄存器配置不一定够，必要时要对照成熟库补全 slot 等兼容配置
4. 调试阶段必须保留关键寄存器回读日志，否则容易把“配置未生效”和“设备不出样本”混为一类问题
5. 嵌入式首轮 bring-up 不要过早删调试日志，先把 I2C 扫描、配置回读、FIFO 指针状态跑通再收敛日志量
6. 串口监视器打开时会占用 COM 口，PlatformIO 上传前需要先关闭监视器，否则会直接卡在 `Could not open COM9`

## 增量更新 2026-05-23 23:xx 采样率与串口刷新率澄清
- 用户反馈：`bpm` 看起来比较稳定，但 `beats` 一度停在固定值，同时对“2Hz 是否等于心率扫描频率”产生疑问
- 本次结论：`2Hz` 只应该理解为串口刷新频率，不应理解为 MAX30102 的实际采样频率
- 当前代码与配置关系：
  - MAX30102 当前 ADC 采样率配置约为 100Hz
  - 由于 FIFO 平均点数当前为 4，因此有效输出到 FIFO 的样本频率约为 25Hz
  - 原先主循环对 FIFO 的轮询节拍是 20ms，等效只有 50 次/秒把“最新样本”送进心率估计器
  - 这意味着传感器虽然在更高频率采样，但估计器看到的是被抽稀后的样本流
- 工程判断：
  - 这属于软件侧的采样/处理节拍不匹配问题
  - 它不会影响串口 2Hz 输出本身，但会影响节拍检测稳定性和 `beats` 连续增长表现
- 已做修正：
  - 明确将 `kSensorConfiguredSampleRateHz` 设为 100Hz，用于启动日志说明
  - 将 FIFO 轮询节拍从 20ms 下调到 10ms，使心率估计器更接近实际采样节拍
- 当前参考算法结论：
  - SparkFun / Maxim PBA 类算法思路：适合做轻量实时峰值检测，特点是 DC 去除 + FIR/低通 + 零交叉 + 峰谷幅值门限
  - Robert Fraczkiewicz 的 RF 算法思路：适合做更稳的窗口化心率与血氧估计，特点是去趋势、相关性检查、自相关找周期和质量门限
  - 当前工程更适合先走 SparkFun/PBA 这类轻量实时路线，待窗口缓存补齐后，再决定是否上 RF 这类窗口算法
