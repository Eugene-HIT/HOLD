## 当前工程主线判断
1. 当前固件主线已经切换到 `xiao_esp32s3_integrated_hold`，并围绕真实硬件链路组织。
2. 整机目标不是单一传感器 demo，而是面向“焦虑检测 + 引导缓解”的挂坠/胸前设备。
3. 当前固件入口已经实际接入以下硬件职责：
   - 主 I2C 传感链
   - 压力触发
   - LRA 震动反馈
   - RGB 状态灯
   - 热反馈 PWM 控制
   - BLE 状态机
4. 当前交互逻辑仍偏 BLE 联调优先，上电后默认进入广告态等待连接，不是纯离线自运行。

## 对 PCB 最重要的现行固件口径
以 [src/xiao_esp32s3_integrated_hold/main.cpp](src/xiao_esp32s3_integrated_hold/main.cpp) 和 [include/project_config.h](include/project_config.h) 为准：

1. 主 I2C：
   - SDA = GPIO5
   - SCL = GPIO6
2. RGB：
   - R = GPIO7
   - G = GPIO8
   - B = GPIO9
3. 热反馈控制：
   - GPIO2，PWM 输出，仅驱动 MOSFET Gate
4. 压力模拟输入：
   - GPIO1
5. 板载用户灯：
   - GPIO21

## 文档与固件之间已发现的板级口径漂移
以下项目会直接影响原理图和 PCB，不宜继续并行保留双口径：

1. DRV2605L 总线口径冲突
   - [docs/2026-06-18-完整小demo接线表.md](docs/2026-06-18-完整小demo接线表.md) 建议 DRV2605L 使用副 I2C：GPIO43 / GPIO44。
   - 但当前整机固件里的 [src/integration/haptic_feedback_manager.cpp](src/integration/haptic_feedback_manager.cpp) 实际是 `hapticDriver.begin(&Wire)`，即直接挂在主 I2C，而不是独立副总线。
   - 结论：PCB 现在必须尽快决定 DRV2605L 是跟 IMU/PPG 共主 I2C，还是保留独立副 I2C；否则固件和板子会错位。

2. 热反馈控制脚冲突
   - [开发指南文档.md](开发指南文档.md) 与 [log/system/2026-06-23-柔性加热片热反馈接线补充.md](log/system/2026-06-23-柔性加热片热反馈接线补充.md) 曾建议使用 GPIO42。
   - 但当前整机固件和整机冒烟环境均已改为 GPIO2。
   - 结论：如果 PCB 已按 GPIO42 画，固件必须同步；如果希望沿用当前固件，则原理图应收口到 GPIO2。

3. MAX30102 是否进入本版 PCB 尚未从网表得到确认
   - 当前代码主线确实有主动/被动 PPG 管理器。
   - 但 [hardware/pcb/netlist/Netlist_Schematic1_2026-07-16.net](../../hardware/pcb/netlist/Netlist_Schematic1_2026-07-16.net) 中未检索到 MAX30102。
   - 结论：现有网表更像外围功能板或分体子板，而不是包含全部传感器的完整终板。

## 从 2026-07-16 网表可确认的内容
当前网表已经明确落地的器件/电路：

1. IMU：MPU-6050 裸芯片方案
2. 触觉驱动：DRV2605L
3. 热反馈开关：AO3400A 低边 MOS 管
4. 电源门控：TPS22810 负载开关
5. FSR/压力模拟前端：含 RC 与分压网络
6. 若干 FLY 接插件用于和主控/电池/外设连接

## 从网表网络名可推断的连接意图
1. `BAT+`：外部电池或上游电源输入
2. `HEAT_CTRL` / `HEAT-`：主控控制热反馈 MOS 管
3. `M_SCL` / `M_SDA` / `M_EN`：马达驱动控制接口，其中 `M_EN` 在现有固件中还没有对应 GPIO 定义
4. `MPU_SCL` / `MPU_SDA`：IMU I2C 接口
5. `TPS_EN`：负载开关使能脚，现有固件中也没有对应控制定义
6. `SW_OUT`：负载开关后的受控电源，供给 DRV2605L、MPU6050 和 FSR 相关网络

## 结合历史路线文档的产品层判断
1. 项目形态仍以挂颈/胸前主机为主。
2. 传感路线层面，历史日志倾向将 ECG 作为更强主路线，但 2026-06-15 后的整机实现阶段，第一版正式集成先不并入 AD8232。
3. 当前整机版实际走的是 IMU + PPG + 压力 + LRA + 热反馈 + BLE 的可演示闭环。
4. 如果这版 PCB 目标是“尽快做出演示样机”，则应优先保证现行整机固件真实使用到的器件和引脚先闭环，不建议同时追求所有长期产品化设想。

## 当前建议的 PCB 收口顺序
1. 先确认这次要画的是“完整主板”还是“外围传感/反馈子板”。
2. 先冻结 DRV2605L 到底走主 I2C 还是副 I2C。
3. 先冻结热反馈控制脚是 GPIO2 还是 GPIO42。
4. 明确 MAX30102 本版是否上板，以及它是板载还是柔性引出到贴肤端。
5. 若要锂电池供电，尽快补充充电、电源路径和保护方案，否则当前网表仍不完整。
6. 若要支持独立工作而不强依赖 BLE 联调，需提前决定是否增加实体按键、开关或专用启动策略。

## 待确认事项
1. 当前 PCB 是主板、子板，还是主板 + 传感头分体结构。
2. MAX30102 是否进入这一版 PCB。
3. DRV2605L 是否必须独立副 I2C。
4. 热反馈控制脚最终锁定到 GPIO2 还是 GPIO42。
5. `TPS_EN` 与 `M_EN` 是打算接 MCU 控制，还是直接硬件固定使能。
6. 电池、充电、保护、开关机路径是否准备在这一版一并落地。
